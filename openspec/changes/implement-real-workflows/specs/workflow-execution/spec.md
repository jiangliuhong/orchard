## Purpose

为工作流提供持久化、可恢复且可观测的真实执行语义，确保步骤结果、重试、取消和幂等行为在进程重启后仍可判断。

## ADDED Requirements

### Requirement: 运行状态必须持久化
系统 SHALL 持久化每次工作流运行、步骤和尝试的状态、输入输出、错误、时间、工作流版本和 artifact 标识，并提供一致的终态转换；运行必须关联 `~/.orchard/` 下已登记且摘要匹配的不可变运行文件。

#### Scenario: 运行完成后可查询
- **WHEN** 工作流所有步骤成功完成
- **THEN** 运行被标记为成功并可查询最终输出及步骤历史

#### Scenario: 进程重启后恢复
- **WHEN** 服务在运行中退出并重新启动
- **THEN** 系统根据未完成的 SQLite 状态恢复或重新领取运行，重新校验并加载其登记的 Node.js/TypeScript artifact，而不是丢失运行

### Requirement: 步骤执行必须支持取消、重试和幂等
系统 SHALL 按配置执行有限次数的重试，支持取消运行，并在同一运行内对相同步骤标识避免重复成功执行。

#### Scenario: 可重试错误
- **WHEN** 步骤以可重试错误失败且尚有重试次数
- **THEN** 系统记录失败尝试并创建后续尝试

#### Scenario: 取消运行
- **WHEN** 用户请求取消尚未完成的运行
- **THEN** 系统停止调度后续步骤、向当前执行传播取消信号并将运行标记为已取消

#### Scenario: 重复步骤请求
- **WHEN** 同一运行再次请求已成功的步骤标识
- **THEN** 系统返回已记录的结果且不重复产生成功副作用
