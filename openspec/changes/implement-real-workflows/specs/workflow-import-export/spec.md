## Purpose

让工作流定义能够在 Orchard 实例之间安全迁移，保留可执行所需的版本、触发器和依赖元数据，同时拒绝不可信或不完整的导入内容。

## ADDED Requirements

### Requirement: 系统必须提供完整的工作流导出
系统 SHALL 导出工作流定义、已发布版本、触发器配置、契约和所需元数据，并使用明确版本化的可移植格式。

#### Scenario: 导出已发布工作流
- **WHEN** 用户请求导出工作流
- **THEN** 系统返回可验证的导出包，其中包含版本信息和源码或编译产物引用

### Requirement: 导入必须先验证再落地
系统 SHALL 在导入包写入系统前验证格式、内容完整性、契约、依赖和安全限制；验证失败时不得部分导入。

#### Scenario: 有效包导入
- **WHEN** 用户导入格式正确且依赖可满足的工作流包
- **THEN** 系统创建未激活的工作流和版本，供用户确认后启用

#### Scenario: 恶意或损坏包被拒绝
- **WHEN** 导入包包含非法代码、路径逃逸、未知不安全能力或校验和不匹配
- **THEN** 系统拒绝整个导入并说明原因，不改变已有工作流
