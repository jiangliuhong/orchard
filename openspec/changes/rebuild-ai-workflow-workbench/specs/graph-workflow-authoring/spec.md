# Spec Delta

## Purpose

让用户通过本地 Agent 的多轮对话创建和修改显式节点流程，由服务负责校验和提交草稿，并通过明确发布动作生成能够反复运行且可追溯的工作流版本。

## ADDED Requirements

### Requirement: 多轮对话创建和修改流程
用户 SHALL 通过选择 Provider、模型并描述需求创建草稿，或基于已发布版本创建修改草稿。后续轮次 SHALL 包含当前流程、脚本、历史消息、节点能力和诊断；Agent SHALL 可以澄清需求而不修改草稿。

#### Scenario: 继续修改分支
- **WHEN** 用户要求将原来的执行条件改为新的 action 值
- **THEN** Agent 获得当前定义和历史，产出可查看的流程及脚本变更，工作流身份保持不变

### Requirement: Agent 变更由宿主校验并原子提交
系统 SHALL 将 Agent 输出视为候选变更，只允许修改草稿内的流程及脚本文件；越界路径、重复操作、身份变更和不支持的文件 SHALL 被拒绝。有效文件变更 SHALL 原子更新草稿并保存校验结果，非法流程可以作为不可发布候选保留以便修复。生成或发布 MUST NOT 执行业务脚本。

#### Scenario: 非法流程可继续修复
- **WHEN** 文件变更合法但流程引用了不存在的节点
- **THEN** 草稿保存诊断且不能发布，用户能继续对话修复，已发布版本不变

#### Scenario: 非法文件变更
- **WHEN** Agent 返回工作目录之外的文件路径
- **THEN** 整轮候选文件变更被拒绝，不发生部分写入

### Requirement: 冲突取消和中断不会覆盖草稿
系统 SHALL 以草稿修订号防止并发覆盖，以请求标识去重，并支持取消创作。取消后的迟到输出 MUST NOT 提交；服务重启 SHALL 保留最后提交的草稿与历史，将未完成轮次标记为中断。

#### Scenario: 生成期间取消
- **WHEN** 用户取消后后端又返回文件变更
- **THEN** 轮次保持取消且当前草稿不被迟到变更覆盖

### Requirement: 用户显式发布工作流
系统 SHALL 仅在用户明确发布且校验通过后创建不可变版本并更新当前版本。发布 SHALL 检查草稿修订号、基线版本和 Provider 配置，重复发布同一请求 SHALL 返回同一版本。发布成功 MUST NOT 自动运行工作流。

#### Scenario: 基线变化
- **WHEN** 修改草稿基于 v1，而工作流已被其他修改发布为 v2
- **THEN** 发布返回冲突，保留草稿并要求以当前版本重新处理，不覆盖 v2
