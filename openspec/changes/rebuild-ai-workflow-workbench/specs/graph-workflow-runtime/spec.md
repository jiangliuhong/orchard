# Spec Delta

## Purpose

按照已发布流程的明确控制和数据关系执行本地节点，保存每次运行的节点结果及路由决策，提供可取消、可观察、可追溯且不隐式重复外部副作用的第一版执行能力。

## ADDED Requirements

### Requirement: 每次运行绑定版本并独立推进
系统 SHALL 校验运行输入，创建新的运行和该版本全部节点的运行记录，沿唯一活动路径执行。Switch SHALL 记录匹配值、选中连线与分支理由；未执行节点 SHALL 最终标记为跳过并说明分支未选中、上游失败或运行终止等原因。

#### Scenario: 同版本不同路径
- **WHEN** 同一版本两次运行得到不同的 Agent action
- **THEN** 各运行独立选择路径、保存结果，并能查看实际走过的连线

### Requirement: 脚本节点在受控子进程执行
Node.js 和 Shell 节点 SHALL 执行版本内固定脚本，使用独立运行目录、结构化输入、明确输出契约和进程控制。Shell SHALL 记录 stdout、stderr、退出码；非零退出、输出不合法、超时和输出超限 SHALL 产生明确失败。取消 SHALL 终止进程组并等待清理。

#### Scenario: Shell 非零退出
- **WHEN** Shell 输出日志后以非零退出码结束
- **THEN** 节点失败并保留日志与退出码，下游不启动，系统不自动重复执行该脚本

#### Scenario: CPU 密集 Node.js 节点取消
- **WHEN** 节点持续计算且用户取消运行
- **THEN** 服务仍能处理取消请求，子进程终止，运行在清理后进入取消终态

### Requirement: Agent 节点输出经过契约校验
Agent 节点 SHALL 使用版本内解析的 Provider 和模型，保存 prompt 输入、结构化输出、可用 usage 与实际模型信息。后端失败、结构化解析失败和 Schema 校验失败 SHALL 终止该节点并给出诊断，不伪造成功结果或自动切换后端。

#### Scenario: 分支结果非法
- **WHEN** Agent 返回的 action 不满足输出约束
- **THEN** Agent 节点失败，Switch 和脚本下游不启动

### Requirement: 事件与节点结果完整且可续读
系统 SHALL 保存运行、节点、尝试、输入输出、日志、错误、路由和时间信息，并提供带顺序游标的事件读取与订阅。刷新或断线重连 SHALL 从已保存事件续读；重复事件 MUST NOT 造成状态重复变化。事件体积 SHALL 有上限，大输出 SHALL 使用产物引用。

#### Scenario: 页面断线后重连
- **WHEN** 用户在运行中断开页面后重新打开
- **THEN** 页面通过快照和游标补齐执行进展，节点最终结果与持久化记录一致

### Requirement: 取消和重启具有明确终态
排队运行 SHALL 可以直接取消；活动运行 SHALL 停止调度后继并清理活动调用，取消提交成功后 MUST NOT 接受迟到成功。服务重启 SHALL 将遗留活动运行标记为中断，并说明外部副作用可能已经发生；第一版 MUST NOT 自动续跑或重试。用户再次运行 SHALL 创建新的运行身份。

#### Scenario: 服务在脚本执行时退出
- **WHEN** 服务重启发现上次未终结的活动运行
- **THEN** 运行标记为中断且保留已有记录，不自动再次执行脚本
