# 页面使用说明

工作流列表显示已发布流程及未发布草稿。“新建工作流”进入创作工作区；“Agent 修改”从当前版本复制草稿。

工作流列表和详情页提供删除操作，草稿也可在列表或编辑页删除。点击垃圾桶后需在弹窗确认，删除工作流将清理其全部版本、关联草稿、对话及运行记录，无法撤销；独立副本不受影响。有生成、发布、排队或执行中的任务时，先完成或取消任务再删除。

## 外观与布局

工作台采用紧凑顶栏、中性灰背景、分组列表和统一控件。强调色用于选中与焦点，成功、失败和运行中使用独立状态色。工作流与 Provider 以连续列表行呈现，减少重复卡片和大标题。

顶栏和设置页都提供浅色、深色、跟随系统三个外观选项。偏好仅保存在当前浏览器的 localStorage，不改变数据库或系统设置；跟随系统时会响应系统主题变化。流程画布、弹出菜单和按需加载的代码编辑器同步使用当前主题。

桌面工作区三栏：左侧多轮对话与 Provider / 模型选择，中间只读流程画布，右侧节点配置和源码。画布支持平移、缩放、选择节点，第一版不支持拖拽连线编辑。窄屏通过“对话 / 流程 / 节点”切换区域。

流程预览使用 180px 宽的紧凑节点，类型图标区分 Node.js、Agent、Shell 和条件分支；长名称与脚本路径省略显示，悬停可查看完整文本。默认分支布局居中，结束节点使用小型胶囊标记。初次适配和“适应视图”最多使用 100% 缩放，少节点流程不会自动放大；已有保存布局保持原坐标。

选中 Agent 节点后可覆盖 Provider / 模型和提示词。工作流默认 Agent 在节点面板的折叠区域。修改名称、配置或源码后点击“保存修改”；有未保存修改时先保存再继续对话。校验失败显示诊断并禁止发布，仍可继续修复。

## 历史对话

创作区左侧是对话选择器。每个工作流草稿有独立的对话空间：顶部为当前对话，向下依次是“历史对话”“需要重建”分组，“已归档”默认折叠。每项显示标题（由首条用户消息自动生成，可手动改名）、状态、Provider / 模型、最近活动时间和最后一条用户消息摘要；点击标题可切换查看该对话的消息，再点一次返回当前对话。

“新对话”保留旧对话及全部历史，旧对话转为历史状态；发送、新建、切换、归档、恢复、发布、测试和删除在存在排队、执行中或取消中的轮次时被锁定。历史对话点“继续”设为当前对话，原当前对话自动转为历史；已归档对话默认只读，展开分组后点“恢复”重新设为当前。归档需二次确认，消息、轮次与审计记录保留，对话停止接收新消息；Provider 侧会话文件不删除。

需要重建的对话（后端上下文中断，例如服务重启后无法安全恢复）只能阅读；顶部提示条提供“重建上下文”，重建会创建全新后端上下文和新对话，并保留原对话作诊断历史。没有任何进行中的对话时发送被禁用，请新建或继续历史对话。

草稿工作区提供“运行测试”。测试要求草稿已保存并通过校验，使用当前修订号创建独立不可变快照；测试会实际执行脚本和 Agent 调用，可能产生外部副作用和模型用量，但不会发布工作流、递增发布版本号或改变当前版本。运行详情返回草稿入口，可继续编辑并再次测试。

源码区域使用按需加载的 Monaco；先选择文件，再查看或编辑。选择 Shell 或 Node.js 节点可以查看关联脚本文件。查看、编辑、发布均不执行脚本。

源码工具栏提供“全屏预览”。全屏视图左侧为文件列表，右侧为当前文件内容，支持切换工作流定义、布局和脚本；顶部显示完整相对路径与编辑状态。草稿中的修改与原编辑区同步，退出后点击“保存修改”写入草稿；已发布版本保持只读。点击“退出全屏”或按 Esc 返回，保留选中文件与尚未保存的编辑内容。

## 最终输出与结果

草稿右侧有独立的“最终输出”标签；点击画布“结束”或在节点选择器中选择“工作流最终输出”也会打开此配置。输出方式包括节点输出、工作流输入、组合多个字段和高级绑定 JSON。字段路径使用 JSON Pointer，留空返回全部，`/summary` 返回 summary 字段。组合字段可分别选择来源节点或工作流输入；数组、常量和嵌套组合使用高级 JSON。

“最终输出 Schema”约束整个流程返回值，`true` 表示不限制，`{"type":"string"}` 表示文本。点击“应用输出配置”进行校验，再“保存修改”后测试或发布。校验会拒绝无效路径、重复字段、非法 Schema，以及并非所有结束路径都执行的节点引用。已发布版本的输出配置只读，历史运行继续使用创建运行时的固定配置。

运行完成后默认打开独立的“最终结果”页面。字符串直接展示正文，对象、数组及其他 JSON 值格式化展示；可以切换“原始 JSON”、复制、下载或全屏阅读。文本预览下载为 `.txt`，JSON 模式下载为 `.json`。较大结果需要显式“加载完整结果”后再预览和导出。

“执行详情”保留流程图、各节点输入输出、日志和执行信息；点击结束节点或选择“工作流最终输出”返回结果页。运行未完成时提示等待，失败、取消或中断不会将节点的中间结果当作最终输出。即使全部节点成功，最终输出路径不存在或不符合 Schema 时，整次运行仍会失败。

已发布详情提供版本选择、当前发布标记、创建时间、“编辑 / 发布新版本”、“复制为新工作流”、“还原到草稿”和运行操作。编辑继续同一工作流已有未发布草稿；复制分配全新工作流 ID，首次发布为 v1；还原将选中历史版本复制为同一工作流草稿，发布后版本号递增并保留历史。运行页展示该次运行固定的版本或草稿测试快照，点击节点查看实际输入、输出、耗时、错误和执行元数据。分支未选择、上游失败与运行终止有不同跳过说明；运行中的节点会更新状态。日志面板展示最近 500 个事件中的当前节点日志，完整事件通过 API 分页读取。

## Provider 设置

Provider 行显示连接状态、模型数量、默认模型、检测按钮和启用开关。开关和默认模型选择即时保存；失败时恢复之前的值并显示错误。

点击该行“配置”展开 CLI 路径或连接 JSON，修改后点击“保存设置”。连接能力在展开区域中查看。

点击 Provider 名称旁的“模型数量”打开模型管理：

- 按名称或模型 ID 搜索，查看模型来源、启用状态和默认标记。
- 使用每个模型的开关即时启停；创作和节点配置只提供已启用模型作为新选择。
- 输入模型 ID、可选显示名称，并选择是否启用后添加。
- 点击删除图标，再确认删除，将模型从该 Provider 的工作台目录移除。
- 刷新目录保留已有启停状态；已删除的自动发现模型不会重新出现，需要时可手动添加同一 ID 恢复。
- 点击模型行的“验证”，通过所选 Provider 发起一次真实模型请求；显示可用、失败或已取消，以及耗时、检查时间和失败原因。后端明确返回不同模型 ID 时会同时展示。

验证可能产生少量模型用量，使用固定短提示词，不附带工作流或对话内容，不自动重试。Provider 必须启用；模型本身可以处于禁用状态，验证不会改变其启用状态或默认模型。每个 Provider 同时只能验证一个模型，最多等待 60 秒；点击“取消”或关闭弹窗会取消请求。检测 CLI 阶段的取消在本地版本检测结束后生效，内建检测最多等待 10 秒。

验证结果只表示这次请求的结果，临时保存在当前页面，不写入数据库。刷新页面或更改该 Provider 配置后需要重新验证。

禁用或删除当前默认模型会清空默认值，不自动切换到另一个模型。已发布流程与历史保留原模型 ID，但后续调用会拒绝已禁用或删除的模型，进行中的调用按原配置完成。模型管理保存在现有 JSON 配置中，不改变数据库表结构。

CLI 可执行与实际账号/模型就绪不同，调用失败会保留真实错误。未启用、未检测、未就绪、空模型目录分别提示，历史失效选择不静默替换。

Codex CLI 沿用本机用户配置，支持 Magpie 自定义网关；无需在工作台重复填写网关或密钥。模型刷新优先读取配置中的 model_catalog_json，未配置时读取默认缓存。模型名称和 ID 分别展示，编排或验证使用目录中的准确 ID，例如路由组的 `group/...`；手动填写的显示名称不会自动猜测为另一个模型。旧模型条目保留，需要时可手动删除。

视觉使用统一的状态文本和颜色；键盘可以到达导航、表单与操作按钮。组件交互测试属于开发检查；真实浏览器的布局、视觉与全链路体验留待后续专项验收。
