# Agent 模型配置

适用版本：数据库 v8 及以后。最后更新：2026-11-07。

Agent 模型配置把一个明确的 Provider 和模型组合保存为可命名的配置，例如「xxx 分析」。工作流引用配置 ID，修改绑定后，后续新创建的运行使用新模型，无需重新发布工作流。

## 创建与修改

1. 在「设置 → Provider」启用连接，并刷新或手动添加需要的模型，确认模型已启用。
2. 打开「设置 → Agent 模型配置」，点击「新增配置」。
3. 填写唯一名称、可选说明，选择 Provider 和明确的模型，点击「创建配置」。
4. 需要调整时点击「编辑」，修改名称、说明、Provider、模型或启用状态，检查引用范围后确认修改。

配置 ID 不随改名变化。每次修改产生新修订；旧修订仍供历史运行查询。只支持启用、禁用，不提供删除接口。修改时如果配置已被另一页面更新，会提示刷新后重试，避免覆盖新版本。

「引用」列按工作流去重，草稿数量单独显示。点击可查看草稿和全部发布版本，包括历史版本。

## 在工作流中使用

工作流编辑页「全局配置 → Agent 默认配置」选择配置名称。Agent 节点默认继承该配置，也可以选择另一项配置单独覆盖。

工作流保存的是 `agentConfigId`，不保存直接调用的 `providerId`、`modelId`。同一节点不能只覆盖 Provider 或只覆盖模型。节点提示词、输入输出和超时仍在工作流中配置。

没有 Agent 节点时不要求选择默认配置。有 Agent 节点时，必须为节点单独选择或设置有效的工作流默认配置。可保存暂时无效的草稿，但发布和运行前必须修复。

## 修改何时生效

| 操作 | 模型选择 |
| --- | --- |
| 发布工作流 | 保留配置 ID，验证引用，不固定当前模型 |
| 新建正式运行或草稿测试 | 在入队事务中保存全部 Agent 节点的配置修订和 Provider 修订 |
| 配置在排队或执行期间变化 | 该次运行继续使用原配置修订 |
| 再次运行 | 使用创建新运行时的最新配置 |
| 重试同一个成功请求 | 返回原运行，保留原绑定 |

运行详情选择 Agent 节点，在「执行信息」查看配置名称、配置修订、Provider 和模型。失败或未走到的节点也保留其创建时绑定，可通过运行详情接口的 `agentBindings` 查询。

配置的启停与底层 Provider、模型的启停分别处理。禁用配置阻止新建运行，不改写已有绑定；底层 Provider、模型被禁用或删除时，尚未开始的调用仍会被拒绝。连接不可达、权限不足或模型报错会明确失败，不自动换模型或使用 Provider 默认模型。

模型绑定不冻结连接密钥或 CLI 路径；节点执行记录保留实际调用的 Provider 修订，便于定位创建运行后发生的连接设置变动。

## 创作对话与范围

工作流和脚本创作对话仍选择 Provider 与模型，不自动切换已有会话。工作流创作 Agent 获得可用配置目录，生成节点时只能引用目录中的配置 ID。

本次不兼容或转换旧工作流的直接模型引用。旧数据保留，但旧格式不能作为新版的有效工作流定义发布或运行。

数据库变更已审核：新增当前配置、历史修订、运行节点绑定三张表，不改变旧工作流数据。完整设计及验证记录见[功能设计](../../features/2026-11-07-agent-model-configs/design.md)。
