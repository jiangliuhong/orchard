# 对话草稿与发布

创作仅使用原生协议，支持单次与多轮逻辑对话。对话记录独立于 Provider 原生 thread/session：多轮复用受控后端会话；单次每轮隔离后端上下文但保留宿主消息。新对话将旧当前对话转为历史，不提高草稿 revision，也不会将创作会话带入发布版本。

旧兼容模式的多轮对话在升级后需要重建上下文，历史消息仍可查看；归档旧对话恢复后也需要重建。重建创建新的原生会话，仅在首次建立后端上下文时带入受限历史摘录，后续续接使用原生上下文。迁移规则见[仅支持原生协议设计](../../features/2026-11-06-native-only/design.md)。

新建工作流先创建独立草稿，包含固定身份的最小 Node.js 流程。用户选择创作对话的 Provider 和模型后描述需求，Agent 获得当前文件、节点协议、可用 Agent 模型配置目录和诊断；生成的工作流只能通过配置 ID 引用模型。多轮历史由原生会话续接，显式重建时提供历史摘录。

Agent 输出结构为 `summary` 和 `changes`。每个变更是 create / update / delete，加受控相对路径，新增和修改必须提供完整文本。`changes: []` 可以用于澄清需求。宿主先校验整批路径，再原子提交完整文件树；不允许通过生成过程执行业务脚本。

图或脚本校验失败的合法文件候选会保存为不可发布草稿，诊断可供下一轮修复。越界路径、身份修改、重复操作等拒绝整轮，不留下部分更新。对话上下文上限 512 KiB。

每轮记录 Provider、明确模型、配置修订、对话和状态。草稿修订号防止覆盖新修改，一个草稿最多一个 `queued`/`running`/`cancel_requested` 活动轮次，请求标识用于重试去重。取消先进入 `cancel_requested`，协议确认或进程回收后才进入 `cancelled`；迟到结果不能更新草稿。服务重启将活动轮次标记中断，接受状态不确定时会话标记为 `needs_rebuild`，不会自动重发，保留最后提交的文件与消息。

用户手动编辑文件或 Agent 节点配置后先点击“保存修改”，此操作更新草稿并重新校验，不生成工作流版本。只有点击“发布工作流”才会固定完整流程与 Agent 模型配置引用，并激活新版本。具体模型在每次创建运行时固定；修改具名配置不需要重新发布，规则见[Agent 模型配置](./agent-model-configs.md)。

修改已发布工作流时从当前版本复制草稿。发布前检查修订号及基线版本，若别人已发布新版本，原草稿保留并报告冲突；需要从最新版本重新创建修改草稿。发布过程文件先固化、数据库后提交，失败不产生可运行半版本。重复同一发布请求返回同一版本。

发布不会自动运行。前往工作流详情手动运行，或继续查看各节点。
