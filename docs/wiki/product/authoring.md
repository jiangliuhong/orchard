# 对话草稿与发布

创作仅使用原生协议，支持单次与多轮逻辑对话。对话记录独立于 Provider 原生 thread/session：多轮复用受控后端会话；单次每轮隔离后端上下文但保留宿主消息。新对话将旧当前对话转为历史，不提高草稿 revision，也不会将创作会话带入发布版本。

旧兼容模式的多轮对话在升级后需要重建上下文，历史消息仍可查看；归档旧对话恢复后也需要重建。重建创建新的原生会话，仅在首次建立后端上下文时完整带入源对话及其重建祖先链的已保存用户、助手和错误消息，后续续接使用原生上下文。历史不按条数或单条大小截断，超过完整 prompt 上限则明确拒绝。迁移规则见[仅支持原生协议设计](../../features/2026-11-06-native-only/design.md)。

新建工作流先创建独立草稿，包含固定身份的最小 Node.js 流程。用户选择创作对话的 Provider 和模型后描述需求，Agent 获得当前文件、节点协议、可用 Agent 模型配置目录和诊断；生成的工作流只能通过配置 ID 引用模型。多轮历史由原生会话续接，显式重建时提供完整已保存历史。新的成功助手消息同时保存完整 proposal（含文件全文）；旧记录若仅保存摘要，不能凭空补回缺失内容。

Agent 输出结构为 `summary` 和 `changes`。每个变更是 create / update / delete，加受控相对路径，新增和修改必须提供完整文本。`changes: []` 可以用于澄清需求。宿主先校验整批路径，再原子提交完整文件树；不允许通过生成过程执行业务脚本。

图或脚本校验失败的合法文件候选会保存为不可发布草稿，诊断可供下一轮修复。越界路径、身份修改、重复操作等拒绝整轮，不留下部分更新。对话上下文上限 512 KiB。

每轮记录 Provider、明确模型、配置修订、对话和状态。草稿修订号防止覆盖新修改，一个草稿最多一个 `queued`/`running`/`cancel_requested` 活动轮次，请求标识用于重试去重。取消先进入 `cancel_requested`，协议确认或进程回收后才进入 `cancelled`；迟到结果不能更新草稿。服务重启将活动轮次标记中断，接受状态不确定时会话标记为 `needs_rebuild`，不会自动重发，保留最后提交的文件与消息。

用户手动编辑文件或 Agent 节点配置后先点击“保存修改”，此操作更新草稿并重新校验，不生成工作流版本。只有点击“发布工作流”才会固定完整流程与 Agent 模型配置引用，并激活新版本。具体模型在每次创建运行时固定；修改具名配置不需要重新发布，规则见[Agent 模型配置](./agent-model-configs.md)。

修改已发布工作流时从当前版本复制草稿。发布前检查修订号及基线版本，若别人已发布新版本，原草稿保留并报告冲突；需要从最新版本重新创建修改草稿。发布过程文件先固化、数据库后提交，失败不产生可运行半版本。重复同一发布请求返回同一版本。

发布不会自动运行。前往工作流详情手动运行，或继续查看各节点。

## 各创作 Agent 的历史上下文

- **工作流 Agent**：多轮模式续接 Provider 原生 thread/session；实际上下文压缩由 Provider 管理，不保证无限保留原文。单轮模式每次隔离。显式重建完整回放源对话及其重建祖先链的已保存用户/助手/错误消息，包含新记录的完整 proposal，不再限制为 20 条/64 KiB 摘录；超过 512 KiB 完整 prompt 上限时明确拒绝，不截断历史。
- **脚本库 Agent**：每轮从持久化记录回放同一脚本、同一对话、同一草稿版本的全部历史用户请求和完整成功 proposal（包括源码、metadata、testInput），不再仅取最近 8 轮摘要。失败、取消、中断轮次保留用户请求、状态和错误；同时提供宿主确认的应用状态及应用修订号。当前完整脚本草稿始终是文件修改基线，历史 proposal 不代表已应用。
- **浏览器桥接 Agent**：每轮回放同一应用、同一对话的全部历史用户请求、完整成功 proposal、轮次状态、错误和应用状态。

脚本库与桥接使用完整历史回放，并非 Provider 原生持久会话；不会混入其他对话。完整 prompt 超过 512 KiB 时明确拒绝并提示新建对话，不静默裁剪历史。这里的完整回复指宿主持久化的 proposal，不包含模型隐藏推理或未保存的失败输出。测试日志等辅助上下文仍有独立长度限制。
