# 脚本库、Agent 创作与版本复用

适用范围：本地单用户工作台，schema v6。最后更新：2026-11-06。

## 创建、编辑和发布

1. 打开主导航“脚本库”，创建脚本并选择 Node.js 或 Shell。ID 创建后固定。
2. 编辑说明、入口文件、源码、输入/输出 Schema 和超时。Node.js 默认导出函数接收 JSON 并返回 JSON；支持 Node 内置模块和版本内完整相对文件引用，不安装 npm 依赖。
3. 保存后检查源码诊断。语法错误可以保存为待修复草稿，但不能发布。未保存内容必须先保存或放弃才能切换版本、测试和发布。
4. 输入测试 JSON 并手动执行，检查输出、日志、错误、退出码和耗时。测试使用提交时的完整快照，后续修改不会改变已排队测试的内容。取消会终止对应进程；重启后已执行中的测试显示中断失败，不自动重试。
5. 点击发布并确认，得到只读版本。发布进行静态检查，不运行脚本；测试和发布均需用户手动发起。

Shell 默认的 `process` 协议返回 `{ stdout, stderr, exitCode }`。如果选择 `json` 协议，脚本必须向 `$ORCHARD_RESULT_FILE` 写入合法 JSON，stdout/stderr 保留为日志。非零退出、超时、结果文件缺失、非法 JSON 或不匹配的输出 Schema 都会失败。输出协议在版本发布后固定。

## 使用 Agent

先创建脚本草稿并保存本地修改，再选择已启用的 Provider 和模型，描述需求并点击“发送”。可以提问、讨论或要求修改。通过输入框下方的“+”添加该脚本的一条测试记录作为上下文，已添加引用可移除。模型调用可能产生用量。

普通回答直接展示在对话中；产生修改时显示变更卡片，点击“查看变更”展示文件和元数据差异。修改可以包括源码新增/替换/删除、允许的元数据字段及可选测试输入；点击应用后还需要确认，宿主才会以一次修订保存。Agent 不执行脚本、不发布，也不能更改其他脚本或工作流。仅建议测试输入或澄清问题的回复无需应用。

应用后手动运行测试；失败时选择该测试结果继续向 Agent 提交修复需求。建议测试输入按钮只填入测试编辑框，不会运行测试。

历史提案基于明确的草稿 ID 和修订号。草稿发生变化后，旧提案只读保留，需重新生成，不能覆盖新的修改。新草稿使用新对话；同一草稿可创建新的对话组。对话每轮重建最近上下文，不复用工作流的原生会话。服务重启将未完成生成标为中断，需重新提交。

## 历史版本和工作流引用

版本列表可查看历史源码、Schema 和元数据。展开“版本差异”选择比较基准，可逐文件查看新增、删除和修改。旧产物若未保存元数据快照，页面会说明名称和描述使用当前值，无法恢复未曾存储的信息。

“复制此版本为新草稿”保留发布版本。存在草稿时，“还原此版本”会在确认后替换当前草稿内容并增加修订；并发修改或草稿 ID 变化会拒绝还原。复制为新脚本会创建独立身份和初始草稿。

工作流草稿中选择 Node.js、Shell 或脚本节点，通过“引用脚本库”选择已发布脚本及固定版本，再保存和发布工作流。版本升级需显式选择并重新发布工作流。明确不兼容的输入绑定或节点 Schema 会阻止发布；复杂 Schema 无法静态判定时会提示，实际运行继续严格检查。

“工作流引用”列出全部已发布工作流版本及未发布草稿中的节点引用，历史引用链接会打开对应的工作流版本。选择新脚本版本时保留更短的节点超时，并按新版本上限收紧。归档会禁止新引用、编辑、发布和新测试，并取消活动生成；历史工作流继续使用原来绑定的版本运行。

## 数据保留与边界

默认保留全部历史，不自动删除。展开“测试数据保留与清理”，设定天数及至少保留的最新记录数，先预览再确认。每次最多删除 1000 条满足条件的已完成测试；运行中的测试保留。仍被其他测试、工作流、版本、命令回执或 Agent 记录引用的产物不删除。清理范围发生变化时必须重新预览。

测试列表分页返回摘要；大输入、输出或日志通过完整产物链接读取。清理后重试原测试请求返回 410；发起新测试需使用新 requestId。

脚本库属于当前 data-dir，沿用工作台的本地来源校验，不提供多用户共享权限。运行环境不继承宿主凭据变量，但进程不是操作系统沙箱；执行的代码仍具有当前系统用户的权限。

实现与验证记录见[脚本库功能文档](../../features/2026-11-06-script-library/design.md)。
