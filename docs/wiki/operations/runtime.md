# 运行状态与数据生命周期

正式运行绑定不可变发布版本；草稿测试绑定不可变草稿快照，不创建发布版本。两者先验证输入并创建该次执行的全部节点记录。首版一个 Run 活动，其余排队；每个 Run 沿唯一选中路径串行执行。

正式运行默认使用 `~/.orchard`；执行 `pnpm dev` 时使用仓库目录下的 `.orchard`。两者都可以通过 `--data-dir` 显式覆盖。

运行状态：queued → running → succeeded / failed；活动取消经过 cancel_requested → cancelled。排队取消直接 cancelled。异常退出后遗留活动状态在下次启动时标记 interrupted，排队记录保留。成功和取消竞争按先提交者确定结果，取消获胜后不接受迟到成功。

节点状态：pending、running、succeeded、failed、cancelled、skipped、interrupted。未选中分支在流程终结时标记 skipped / branch_not_selected；上游失败使用 upstream_failed；取消或中断使用 run_terminated。共享后继不在初次选路时提前跳过。

Switch 记录匹配值、选中连线和理由。Agent 输出必须满足声明的 Schema，非法结果不会传给下游。超时属于失败，和用户取消区分。每个执行节点有 attempt，记录输入输出、配置、实际模型或进程元数据与时间。

默认不自动重试，也不从中断节点续跑。再次运行产生新 Run，外部副作用可能重复。进程控制会先 SIGTERM，随后 SIGKILL，服务等待清理后再结束取消；不能撤销已经发生的文件、网络或其他业务操作。

## 数据

新数据目录包含 `workbench.db`、`workbench.lock`、`artifacts/trees`、`artifacts/blobs` 和每次运行的 `runs/` 工作目录。当前数据库有十六张业务表，`application_id = 1331110449`、`user_version = 6`。初始结构批准于 OpenSpec 设计 D10，后续结构与迁移审核保留在各 feature 中。支持的工作台历史 v1～v5 和桥接配置 v0 必须经迁移向导确认后升级；Store 只打开已就绪的 v6 数据库，不再隐式建表或升级。不迁移旧 Orchard 产品库。

流程文件和编译产物以完整摘要固化；节点启动前验证。较大 JSON 结果写入摘要产物，API 返回引用，完整结果由产物端点显式读取。结果超过 16 MiB、进程输出超过 8 MiB 会失败。日志分块保存，事件按 stream 分配单调 sequence，事务提交后才通知订阅者。

版本、节点与请求去重均有唯一约束；版本禁止更新。历史不自动删除。用户显式删除工作流时，以事务清理其版本、草稿、对话、运行、节点执行、事件和相关请求回执；存在活动任务时拒绝删除。删除单个未发布草稿不影响发布版本和其他草稿。固化的摘要树、结果产物和运行工作目录不在此操作中回收，避免误删共享文件。仅 staging 可在启动时安全清除；无引用文件保留，后续可按明确引用扫描做回收。

需要备份时停止服务并完整复制新数据目录；恢复时使用同一版本应用和匹配的数据快照，保留产物与数据库的一致性。未来变更表结构须另行审核并先备份，不能只修改 user_version 回滚。

## 启动、迁移与恢复

进程先获取数据目录租约，再启动最小 HTTP；检查、备份与转换在 worker 中运行。`/api/health` 表示 HTTP 存活，`/api/ready` 仅在数据和业务容器都就绪后返回 200。检查、迁移或恢复期间，业务 API、SSE 和 Bridge 代理返回 `503 / NOT_READY`，不启动业务队列或 Provider 会话。

空目录通过持久化初始化协议建立当前数据库与 v1 配置；已就绪的历史当前库可建立账本基线。支持的旧工作台进入向导，用户预览、补充信息并确认后，任务先完整快照登记资源，再在副本转换，逐文件安装，最后提交账本。目录身份不明、结构不符、缺链、过新版本或包完整性校验失败时保留数据并阻止业务启动，不会静默更换目录。

登记资源包括 workbench.db、config、artifacts、runs、script-agent、agent-sessions、agent-workspaces。`backups/migrations/<jobId>/` 保存可验证快照与清单；`migrations/jobs/<jobId>/` 保存任务和安装记录；ledger.json 是版本历史。私密答案仅在权限受限的 private-input.json 中短暂保存，任务提交、失败或恢复完成后清除。目录外工具会话只保留原始引用，不属于自动备份。

进程异常退出后按持久化阶段处理：安装前保留正式输入并将尝试标记失败；安装未提交则自动恢复已登记资源；已提交不按旧目标摘要覆盖后续业务写入。未知内容、权限变化、损坏快照或协议冲突进入 recovery_required，先排除冲突再从向导重试恢复。不要手动删除账本、锁、初始化或安装记录来绕过检查。

迁移已提交但业务初始化失败时，重试初始化会保留迁移提交，不重新迁移或恢复旧数据。任务请求、初始化和恢复操作均有持久化去重记录；刷新页面、重发相同请求和打开两个标签页不会启动两次迁移。

发布执行 `pnpm migration:check` 后构建，构建产物附带 migration-integrity.json；运行时再次核验。构建和启动不会自动重锁变化内容。已发布的迁移定义不能改写；后续变更必须新增标识和审核材料。详见 [数据迁移设计与验证](../../features/2026-11-06-data-migration/design.md)及 [验证记录](../../features/2026-11-06-data-migration/verification.md)。
