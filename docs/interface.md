# 页面使用说明

工作流列表显示已发布流程及未发布草稿。“新建工作流”进入创作工作区；“Agent 修改”从当前版本复制草稿。

## 外观与布局

工作台采用紧凑顶栏、中性灰背景、分组列表和统一控件。强调色用于选中与焦点，成功、失败和运行中使用独立状态色。工作流与 Provider 以连续列表行呈现，减少重复卡片和大标题。

顶栏和设置页都提供浅色、深色、跟随系统三个外观选项。偏好仅保存在当前浏览器的 localStorage，不改变数据库或系统设置；跟随系统时会响应系统主题变化。流程画布、弹出菜单和按需加载的代码编辑器同步使用当前主题。

桌面工作区三栏：左侧多轮对话与 Provider / 模型选择，中间只读流程画布，右侧节点配置和源码。画布支持平移、缩放、选择节点，第一版不支持拖拽连线编辑。窄屏通过“对话 / 流程 / 节点”切换区域。

选中 Agent 节点后可覆盖 Provider / 模型和提示词。工作流默认 Agent 在节点面板的折叠区域。修改名称、配置或源码后点击“保存修改”；有未保存修改时先保存再继续对话。校验失败显示诊断并禁止发布，仍可继续修复。

源码区域使用按需加载的 Monaco；先选择文件，再查看或编辑。选择 Shell 或 Node.js 节点可以查看关联脚本文件。查看、编辑、发布均不执行脚本。

已发布详情提供版本选择。运行页展示该次运行固定的版本流程，点击节点查看实际输入、输出、耗时、错误和执行元数据。分支未选择、上游失败与运行终止有不同跳过说明；运行中的节点会更新状态。日志面板展示最近 500 个事件中的当前节点日志，完整事件通过 API 分页读取。

## Provider 设置

Provider 行显示连接状态、模型数量、默认模型、检测按钮和启用开关。开关和默认模型选择即时保存；失败时恢复之前的值并显示错误。

点击该行“配置”展开 CLI 路径或连接 JSON，修改后点击“保存设置”。连接能力在展开区域中查看。

点击 Provider 名称旁的“模型数量”打开模型管理：

- 按名称或模型 ID 搜索，查看模型来源、启用状态和默认标记。
- 使用每个模型的开关即时启停；创作和节点配置只提供已启用模型作为新选择。
- 输入模型 ID、可选显示名称，并选择是否启用后添加。
- 点击删除图标，再确认删除，将模型从该 Provider 的工作台目录移除。
- 刷新目录保留已有启停状态；已删除的自动发现模型不会重新出现，需要时可手动添加同一 ID 恢复。
- 点击模型行的“验证”，通过所选 Provider 发起一次真实模型请求；显示可用、失败或已取消，以及耗时、检查时间和失败原因。后端明确返回不同模型 ID 时会同时展示。

验证可能产生少量模型用量，使用固定短提示词，不附带工作流或对话内容，不自动重试。Provider 必须启用；模型本身可以处于禁用状态，验证不会改变其启用状态或默认模型。每个 Provider 同时只能验证一个模型，最多等待 60 秒；点击“取消”或关闭弹窗会取消请求。检测 CLI 阶段的取消在本地版本检测结束后生效，内建检测最多等待 10 秒。

验证结果只表示这次请求的结果，临时保存在当前页面，不写入数据库。刷新页面或更改该 Provider 配置后需要重新验证。

禁用或删除当前默认模型会清空默认值，不自动切换到另一个模型。已发布流程与历史保留原模型 ID，但后续调用会拒绝已禁用或删除的模型，进行中的调用按原配置完成。模型管理保存在现有 JSON 配置中，不改变数据库表结构。

CLI 可执行与实际账号/模型就绪不同，调用失败会保留真实错误。未启用、未检测、未就绪、空模型目录分别提示，历史失效选择不静默替换。

Codex CLI 沿用本机用户配置，支持 Magpie 自定义网关；无需在工作台重复填写网关或密钥。模型刷新优先读取配置中的 model_catalog_json，未配置时读取默认缓存。模型名称和 ID 分别展示，编排或验证使用目录中的准确 ID，例如路由组的 `group/...`；手动填写的显示名称不会自动猜测为另一个模型。旧模型条目保留，需要时可手动删除。

视觉使用统一的状态文本和颜色；键盘可以到达导航、表单与操作按钮。组件交互测试属于开发检查；真实浏览器的布局、视觉与全链路体验留待后续专项验收。
