# 迁移执行与恢复审核基线

状态：待审核，尚未接入执行器。本文与锁定 SQL 共同计算审核候选清单摘要；通过审核不等于实现或验证完成。

完整产品契约见 [设计第 5～9 节](./design.md#5-启动架构)。以下是本次审核的执行边界，后续实现不得弱化；实现新增依赖、校验器及执行代码后须重新计算清单并补充审核，当前候选 checksum 不冒充最终发布 checksum。

## 执行

1. Bootstrap 独占目录锁，按 application_id 1331110449、user_version 和独立版本基线只读识别数据。确认前不得打开业务 Store、加载可补写配置或启动后台任务。
2. v1～v5 依次执行余下的固定 SQL，目标 v6；v6 不执行结构迁移。新安装显式使用冻结的 v6 初始化 SQL，不从残留或未知目录创建空库。
3. 用户确认源逻辑指纹、计划及全部答案后，先持久化 accepted 和去重信息再返回 202。所有扫描、数据库校验、推演和转换由 worker 执行，HTTP 状态查询不等待同步转换。
4. checkpoint 成功、关闭源数据库连接后备份主文件。快照覆盖 workbench.db、config/、artifacts/、runs/、script-agent/、agent-sessions/、agent-workspaces/，记录存在性、空目录、权限和摘要。不跟随符号链接，不复制目录外会话；不覆盖运行时认证 token。
5. 备份及清单全部刷新、核验后落盘 backup_complete。转换只操作独立工作副本。SQLite 外键暂时关闭的表重建必须在副本事务内执行，提交前后检查结构、外键、完整性及逐迁移不变量。
6. 副本 checkpoint、关闭连接并刷新；重新核对正式源逻辑指纹。按声明只安装数据库和发生变更的配置，不重写历史产物和会话目录。全部安装临时文件、目标摘要和清单落盘后标记 prepared。
7. 先落盘 installing，再逐项 rename 正式资源；每项刷新文件及父目录并记录进度。校验正式位置后 installed，原子刷新账本，再 committed。此前账本的存在性及完整副本单独保存。
8. committed 后清除秘密输入，再初始化业务。初始化失败只允许重试初始化，不将已提交迁移改为失败，不回滚。任务调度器仅在 ready 后运行。

## 恢复

| 最后持久化阶段 | 重启处理 |
| --- | --- |
| accepted / backing_up | 核验原数据，标记失败；不从不完整快照恢复 |
| backup_complete / transforming / verifying / prepared | 核验原数据，结束旧尝试；重新预览、确认，不自动重跑 |
| installing / installed，包括账本写入后但未 committed | 验证快照与清单，恢复全部安装项及迁移前账本，再核验完整资源边界 |
| restoring / recovery_required | 幂等继续恢复；未知正式内容、备份损坏或证据不足时保持 recovery_required |
| failed / restored | 保留结果；重新确认创建新的 job，attemptOf 指向原 job |
| committed | 按当前目标、结构、不变量和账本路径校验，不重复执行；业务开放后的正常写入不再与旧目标字节比较 |

恢复仅能覆盖清单中已知的迁移前值、目标值或受控恢复临时值；发现外部修改不得强行覆盖。恢复采用正式位置同目录临时文件，刷新、核验、rename、目录刷新后记录进度。原本不存在的新增资源恢复时删除并刷新父目录。数据库安装和恢复前关闭全部连接并处理 WAL/SHM，防止旧日志重放。

状态、清单和账本使用同目录临时写入、文件刷新、rename、目录刷新协议；目录 0700、文件 0600。目录锁从检测保持至 worker、HTTP 和全部连接停止；worker 不另开 Store 争锁。阶段标记未落盘时只能按此前持久阶段处理。

## 新安装

initialization.json（formatVersion 1）记录 kind、源存在性、临时目标摘要和逐资源进度。阶段 preparing → prepared → installing → committed。prepared 前禁止替换正式资源；重启按记录幂等完成，不重新判空。仅缺失的可选 web-bridge.json 可以初始化为空 v1，不修改既有数据库；损坏或空文件不算缺失。初始化 committed 后建立 baseline 账本，不伪造历史 SQL 执行记录。

## 不变量与验证责任

每段 SQL 的行映射和目标差异见 [审核材料](./schema-review.md)。必须核对数据库身份、版本、基线结构、完整性、外键、各旧表行数、历史不可变内容及全部有效引用；Provider JSON 和本地会话内容只校验保留。配置转换仅增加版本和缺失顶层映射，保留未知字段，拒绝重复键及无效嵌套类型。

独立冻结 v1～v6 夹具、逐阶段强杀、双进程锁竞争、空间不足、WAL busy、外部写冲突、初始化清理、全资源恢复和 M01～M30 验收均仍是实现后的交付条件。当前只冻结待审 SQL，不执行结构 SQL、不生成数据库夹具、不做迁移演练。
