## 夹具和协议证据

- 历史数据库基线从独立历史声明式结构建立，来源为 v1 `8a63292`、v2 `d6bacf9`、v3 `19ecca5`、v4 `d759efd`、v5 `0fde3d3`、v6 `265d948`。v5 是同次历史提交内的中间格式，从当时 v6 声明式结构只去掉 timeout_ms 并设置版本 5；没有执行待测升级 SQL 生成期望结构。完整来源见 [provenance.json](../../../tests/fixtures/migrations/database/provenance.json)。
- 数据包含 Provider、草稿、工作流版本、运行/节点/事件/请求回执、对话和脚本；引用指向实际摘要树、产物和托管资源。逐值比较包含 NULL、整数、浮点、字符串、BLOB 和状态映射。
- WAL 测试验证只读 SQLite backup 包含已提交帧、不 checkpoint 源 WAL；固定读事务阻止 checkpoint 时安全失败。只读根目录、复制/安装 ENOSPC、外部写入和恢复冲突使用临时目录验证。
- 持久化工具测试记录真实 fsync、rename、unlink 调用，验证文件先刷新、rename 后刷新父目录，文件刷新失败不替换旧文件。强杀测试在独立进程停止于边界后 SIGKILL 并重启；此证据不等于物理断电测试。
- 接受任务先在 migrations/accepting 中完整写入状态和私密输入，再原子发布到 jobs 并刷新目录。未发布内容不会成为执行任务，重启清除其中的临时私密输入；已发布内容按持久化阶段恢复。
- 通用问题使用测试专用声明，首批生产迁移没有手填问题；测试问题不注册到生产迁移链，也不能通过 HTTP 启用故障注入。
- 步骤 checksum 与发布完整性分开：所有源码、构建脚本、HTML、Vite/TypeScript 配置、锁文件和独立夹具进入发布校验表；步骤只绑定声明、SQL/协议及迁移执行依赖。隔离复制后调整 UI 并显式冻结新发布，发布摘要变化而所有历史步骤 ID/checksum 保持一致。
- 开发代理仅将来自其自身 loopback origin 的请求规范到后端 origin，并重写 Host；不同端口、其他站点和 null origin 原样交给后端拒绝。自动化代理集成与真实 Chromium 的 GET 握手、POST 确认均通过。
