## 1. 目标、范围与现有基础

将“找到目标、选择版本、重复填写参数、执行”压缩为“找到卡片、执行”。一张卡片绑定一个工作流、脚本或浏览器工具，以及一套固定手动参数和参数来源绑定。同一目标可以对应多张不同配置的卡片。固定配置不代表固定结果：外部数据、环境变量、字典和登录状态可能变化。

首期包含：卡片新建、编辑、复制、删除；可检索多层分组与分组维护；组合筛选；三类目标启动；统一运行记录、详情和底层记录入口；表单 / JSON 参数编辑及环境变量、字典引用。工作流和脚本绑定已发布固定版本，发布新版不自动升级卡片。浏览器工具使用明确目标与完整契约摘要，不宣称已有不可变代码版本。

不包含：定时调度、批量执行、多用户共享、任意粘贴脚本执行、全局快捷键、跨设备自动同步和配置 Git 导出。首期不自动清理统一运行记录。

已核查的现有实现及接入边界：

| 能力 | 当前实现 | 本需求的接入方式 |
| --- | --- | --- |
| 工作流运行 | `src/server/app.ts` 的 `/api/workflows/:id/runs`，`src/runtime/runner.ts` | 复用执行引擎；增加统一记录上下文、参数来源和隐私策略传递 |
| 脚本执行 | `/api/scripts/:id/tests`，现有脚本测试服务 | 复用已发布版本测试协议；页面统一称执行，不另建脚本引擎 |
| 脚本参数 | `ScriptTestParameters.tsx`、`BridgeParameterInputs.tsx` | 提炼共享参数组件，保留现有字典引用、输入校验和编辑保护 |
| 浏览器工具 | `src/web-bridge/gateway.ts` | 补齐显式运行环境、确认凭证、执行前 ID 和生命周期事件 |
| 浏览器历史 | `src/web-bridge/history.ts` | 现有结束后写入、最多 500 条的文件历史不能作为新的统一记录事实来源 |

## 2. 页面与交互

### 2.1 快速执行

新增主导航及路由 `/quick-launch`。保持现有工作流、脚本库、网页桥接入口；统一运行记录使用 `/runs`，保留既有工作流运行详情深链接。

顶部固定放页面名称、新建入口；下面是分组、含子分组、搜索、搜索字段、目标类型、可用性、排序和清除筛选。分组不占独立侧栏。卡片使用约 105px 高的紧凑三行布局：类型图标与名称、单行备注、最近状态与执行按钮。名称打开详情，卡片空白区域不触发执行。

详情完整展示名称、备注、分组路径、目标及版本、浏览器运行环境、允许回显的参数与引用、不可用原因、最近执行及历史入口。主要操作为编辑、执行；复制、删除放在次要菜单。复制生成新 ID，不复制历史；删除配置不删除目标或历史，也不中断已提交任务。

正文约 13px，沿用现有灰阶、边框、圆角与主题变量，复用 Button、Dialog、输入组件。支持浅色、深色和跟随系统；窄屏单列卡片、工具栏换行，详情与管理弹窗可滚动，主要操作可达。图标有可访问名称，状态包含文字，结果以 live region 公告。页面只保留操作文案，技术说明放在文档。

### 2.2 检索与排序

搜索去除首尾空白、忽略大小写、按空格分词；词之间 AND，所选字段之间 OR。默认匹配名称、备注、完整分组路径，可限定单字段；不搜索参数和密钥。分组、搜索、类型、可用性之间 AND。

父组默认包含全部后代，可关闭“含子分组”；支持全部、未分组。默认名称升序，可按最近更新降序，ID 作为稳定次序。显示匹配数与总数；无匹配保留筛选并提供清除，真实空库提供新建引导。筛选与排序写入 URL 查询参数，返回和刷新可恢复。

### 2.3 卡片编辑

名称必填，去空白后 1–80 字；备注 0–500 字；每张卡片属于零或一个分组。允许同组卡片同名，但保存前提示区分用途。目标和参数验证见第 4、5 节。

更换目标保留现有手动输入及引用，并标记需要重新校验，不自动套用默认值覆盖编辑。删除或改名的字段引用必须显式解除。版本升级需显式选择、展示兼容性结果并保存。编辑使用 revision 乐观锁，冲突保留本地输入并提示重新加载；运行中编辑只影响后续执行。取消或 Esc 不改变已保存配置。

## 3. 分组选择与管理

筛选及卡片编辑统一使用可检索的树形浮层。搜索匹配名称或完整路径，保留命中项祖先并自动展开；清空恢复此前展开状态。展开箭头与选择名称分开，搜索/折叠不改变选中值。选择才提交，Esc 或外部点击取消并归还焦点。正式版补齐 tree/treeitem 层级、上下/左右方向键、Home/End、Enter 和 Tab 操作。

下拉底部固定“管理分组”，打开应用内管理弹窗：左侧可检索层级及后代卡片数量，右侧名称、父分组、影响数量、保存与删除。

- 新建默认以当前选中组为父级，也可选顶层；名称 1–40 字，同父级不重名，首期不允许斜杠。
- 重命名不改变稳定 ID；移动修改 parentId，整个子树及卡片关系保留。最多 5 层，按移动后最深后代验证，不可移入自身或后代。
- 删除确认展示子分组数和卡片数，目标排除整个被删子树；选择其他组或未分组后，删除整个子树，将其中卡片统一迁移，不删除卡片或历史。
- 删除采用预览 token，绑定子树、卡片集合和相关 revision；确认时若发生并发变化，拒绝旧预览并要求重新预览，不能扩大已确认范围。迁移与删除同事务完成。
- 分组新建/移动/重命名同样在事务中校验同父重名、无环和深度；删除与卡片保存竞争时不得产生悬空 groupId。

名称路径用于显示和搜索，持久关系使用 groupId/parentId。重命名/移动刷新卡片当前路径，但不改运行时路径快照。原型的路径字符串实现不是正式存储方案。

## 4. 执行目标契约

### 4.1 工作流与脚本

工作流目标为 `{workflowId, versionId}`，脚本目标为 `{scriptId, scriptVersionId}`；版本必须存在、已发布且属于指定目标。执行前复核归属、可执行性及输入定义。归档/删除或失效版本使卡片不可用，提供修复入口，不能偷偷改用最新版。

### 4.2 浏览器工具

浏览器目标必须保存以下配置，不能仅存一个工具 ID：

| 字段 | 规则 |
| --- | --- |
| applicationId、toolId | 合起来定位工具，检查应用与工具启用状态 |
| transport、contractDigest | 从目标取得；摘要覆盖参数/凭据 Schema、执行定义、风险/确认策略、超时上限及影响行为的默认配置，复用并核对既有完整工具 hash |
| environmentId、environmentDigest | 使用环境的工具必填；即使当前只有一个环境，也在保存时显式绑定。摘要覆盖 origin、profileId 及相关执行配置，不含凭据值 |
| timeoutMs | 正整数，不超过目标上限；保存和启动时都校验 |
| credentialBindings | 仅保存字典等受控引用，不允许卡片持久化明文凭据；不混入业务 inputSources |
| pagePolicy | 引用工具已有页面匹配策略并纳入契约摘要；不固定易过期的 tabId，也不自动选择另一浏览器资料 |

正式目标选择器展示所需环境与超时设置；已审核原型未接真实环境枚举，此处是服务接入必须补齐的字段。对不使用环境的旧工具适配器，明确返回能力 `requiresEnvironment:false`，environmentId 必须为空；不得从缺省字段推断能力。

调用前复核契约和环境摘要。环境删除/停用、profile 解绑、契约变化均阻止启动并提示重新绑定；连接离线、无匹配页签或匹配不唯一提示修复，不退回另一个环境。HTTP transport 不要求浏览器在线；只有 browser transport 才检查资料连接、页面与登录前置条件。

工具风险为只读且无需确认时直接提交。其他工具先显示应用内确认，列出目标、环境、操作后果与脱敏参数；服务端生成短时确认 token，绑定卡片 revision、目标/环境摘要、参数配置摘要和 requestId，客户端不能直接传 `approved:true` 绕过确认。token 有效期 5 分钟，同一 requestId 可安全重试；配置变化使其失效，取消/Esc 不提交运行。运行时来源值在最终接收执行时解析，不把确认窗口内的临时预览值当执行输入；确认文案标明引用将在启动时读取。

## 5. 输入定义、录入与参数来源

### 5.1 区分契约有效性与表单能力

三类目标统一返回 `{schema, schemaDigest, targetRef, formSupported, unsupportedReason}`：工作流使用固定版本 definition.inputSchema，脚本使用固定版本 inputSchema，浏览器工具使用 parameters。

| 输入定义情况 | 行为 |
| --- | --- |
| 有效且表单可渲染的 object Schema | 默认表单，可切 JSON |
| 有效但根为数组/标量，或包含表单不支持的合法组合/$ref | JSON 模式可保存、执行，仍进行完整 Schema 校验；表单禁用并解释原因 |
| 合法 true Schema | JSON 模式可执行，提示未声明字段约束，不将其解释为“无需参数” |
| 合法 false Schema | 明确提示目标不接受任何输入，无法创建可执行配置 |
| 缺少定义、非法 Schema、无法解析的引用 | 阻止启用，提示修复目标定义；已有配置保留但不可执行 |

不因表单能力有限而判定合法目标需要重写。JSON 数据类型按目标 Schema 决定，不能统一强制 object。JSON Schema 缺省 required、title、description 是合法的，不作为启用条件。无参数目标建议明确空 object 约束。

表单支持基础类型、enum，object/array 使用字段内 JSON 编辑器；未知字段按 additionalProperties 校验，往返不得静默丢弃。复杂 Schema 使用既有校验器的受支持方言和本地引用解析，不新增运行时网络取 Schema。UI metadata 不改变业务校验。

缺失/非法定义在源目标修复：复用 SchemaEditor 补齐工作流输入编辑入口、浏览器参数编辑；工作流/脚本发布新版本后显式升级卡片，浏览器更新后重新绑定摘要。修复入口和兼容扫描属于后续实施任务，不在本轮更改目标或旧版本。

### 5.2 表单 / JSON 与引用图标

复用 ScriptTestParameters、BridgeParameterInputs 与 CredentialDictionaryPicker 的结构。手动输入框右侧 BookOpen 图标打开“引入环境变量”选择器；两栏分别检索来源和变量/Key，仅显示名称、类型、可用性。选中匹配项立即绑定；输入区显示可点击更换的等宽引用，右侧 Unlink 解除并恢复空输入。取消/Esc 不改绑定并恢复焦点，不关闭下层编辑弹窗。数组/对象多行输入的图标顶部对齐。

手动参数使用 `fixedInput`，引用使用独立的 `inputSources`，以编码后的 JSON Pointer 定位。引用覆盖同名手动字段，绑定时移除旧手动值；JSON 中人为添加同名值不能覆盖引用，保存时移除并提示。`${ENV}` 或 `{{...}}` 仅是普通字符串/显示文本，不启用模板插值。

JSON 无效时禁止切入表单且保留原文；表单局部输入不能转换时阻止切换且保留编辑。保存校验手动部分与绑定合法性，解析引用后再校验完整输入。引用只支持可静态确定的已声明顶层对象字段；JSON-only 复杂目标可执行，但不能绑定无法确定的路径。界面和服务端采用同一能力判断。

### 5.3 环境变量和字典

`inputSources` 为 JSON Pointer 到来源的映射，首期支持：

- `{source:"dictionary", dictionaryId, key}`：沿用既有普通/加密字典引用与类型规则。
- `{source:"environment", name, valueType}`：读取当前 Orchard 执行宿主允许名单中的变量。不是页面全局变量，也不透传整个进程环境。

设置中维护允许引用的变量名与类型，默认空名单；只暴露名称、类型及可用性，不提供取值查询 API。配置变动需要乐观锁，允许名单版本加入启动检查。string 原样读取；其他类型严格 JSON 解析，再按字段 Schema 校验，不宽松强制转换。已绑定变量缺失、未允许或解析失败一律阻止执行，不回退空字符串或旧手动值。

每次接收执行时解析一次，冻结为本次内存输入；不因排队、单次运行内读取或网络重试重新解析。重试查询优先命中 requestId，再执行任何来源解析。不同的新执行允许读取最新值。

共享 InputSources 规范化/解析/剔除/隐私策略，适配三类执行服务；现有脚本仅支持 dictionary，环境来源是拟新增能力。浏览器凭据引用仍独立于业务参数。

## 6. 敏感值的配置、执行与历史策略

首期选择**敏感字段只存引用，不在快捷卡片中加密保存手动秘密值**，避免新增一套密钥存储。普通手动值才允许写入 fixedInput。

敏感范围包括明确标注 sensitive/writeOnly 的字段、x-history 禁止记录的路径及其后代、浏览器凭据；根禁止记录则覆盖整个输入。加密字典、所有环境变量解析结果默认按敏感值处理。无法确定复杂 Schema 的敏感路径时采用保守整段保护，不能因为表单禁用而绕过。

- 卡片保存前在服务端检查未剔除的原始手动输入。敏感路径若含手动值，返回字段级错误，要求改用引用；不得先写日志、请求回执或配置再脱敏。
- 嵌套敏感字段首期可引用其已声明顶层父字段的完整对象；无可引用顶层路径（如敏感标量根）时暂不允许持久快捷配置，说明此限制来自敏感存储策略，而非 Schema 非法。
- 字典敏感值要求加密字典，普通字典不作为秘密值绕过入口。变量选择器和来源摘要不回显值。未标注的业务字段无法自动识别秘密，输入说明提示使用引用存放凭据。
- 卡片详情、复制仅返回/复制允许记录的手动值及引用描述，不解析引用；复制不复制确认 token、执行 ID 或结果。首期不提供导出和 Git 同步，也不把卡片配置自动加入现有导出集合。
- 敏感运行的整个输入、输出、节点中间值、流式事件与日志均按既有保守策略屏蔽，仅保留安全状态、错误码及来源描述；策略必须传入底层服务，不只在统一页面隐藏。
- 执行快照持久化安全手动值、引用描述、配置 revision 与目标摘要；真实解析值只驻留任务内存，结束后释放。底层不得将这些值写入产物、错误详情或 command receipt，幂等摘要使用既有受保护摘要机制。
- 若进程重启导致敏感输入丢失，未完成任务标记中断或待确认，不从当前环境重新取值后自动恢复执行。普通字典引用若本次解析结果也仅存内存，同样按此规则处理，不得用当前字典值替代已接收输入。用户明确发起新运行才重新解析。

以后若要支持手动秘密值加密保存，应独立设计加密存储、轮换、复制和导出规则，不属于本期隐式能力。

## 7. 启动、幂等与统一状态

1. 客户端锁定执行按钮，生成 requestId，提交卡片 ID、revision；必要时先完成第 4 节确认。不允许请求覆盖固定参数。
2. 服务端先查幂等回执。同作用域、同 requestId、同配置摘要返回同 executionId；同键不同载荷返回 409。卡片编辑/删除后重试已接收请求仍返回原记录，不再重新验证当前卡片启动新任务。
3. 新请求验证 revision、确认凭证、单实例占用并分配 executionId，保存安全配置快照；执行业务动作前必须提交接收记录。身份/请求格式无效或未知卡片请求不创建业务运行。
4. 检查目标、环境、来源、最终 Schema；失败写入“启动失败”，不发底层调用。成功以同一 executionId 绑定底层任务并提交排队意图，返回 202 与记录地址。
5. 排队 → 运行中 → 成功 / 失败 / 已取消 / 已中断。执行中取消先进入“取消中”，不承诺撤销已有副作用；仅能力支持时显示取消按钮。

统一持久状态编码：`accepted`（已接收/前置检查）、`queued`、`running`、`cancel_requested`、`succeeded`、`failed`、`cancelled`、`interrupted`、`start_failed`、`unknown`（待确认）、`unresolved_closed`（结果未知但已结束追踪）。以下状态占用卡片： accepted、queued、running、cancel_requested、unknown。前置检查期间崩溃且确定未派发时标记 interrupted；不能无记录地遗留占用。

“提交中”是客户端未获响应的状态，不作为持久任务状态。“状态待确认”用于已可能发出外部请求但无法确认结果的服务端记录；客户端暂时断网只标记连接状态，不覆盖服务端终态。“启动失败”和“已中断”是明确终态；浏览器同步适配器可跳过排队阶段。

同卡片仅允许一条未终结执行，范围包括排队、运行、取消中及待确认；不同卡片不承诺对业务操作全局去重。待确认不能自动释放占用后重发，需查证底层结果或用户确认结束追踪；结束追踪不代表撤销副作用，新运行仍需显式操作。

幂等作用域采用入口与稳定目标身份，例如 `quick-launch:<launchId>`；统一索引唯一键为 `(requestScope, requestId)`。服务端传稳定底层请求 ID，不直接复用可能跨入口碰撞的客户端键。对不具备外部幂等的工具，只能保证同一次接收不被自动重复派发，不能宣称外部副作用 exactly-once。

可用性独立于上次执行结果：就绪、目标/环境失效、输入不兼容、连接离线、引用缺失等分别显示。运行失败不自动使配置永久失效；修复临时依赖后重新检查可用性。

## 8. 统一运行记录与浏览器历史改造

### 8.1 范围、列表和详情

汇总当前 data-dir 的工作流正式/草稿运行、脚本测试、网页桥接调用，以及快速执行入口。UI 来源区分快速执行、工作流页面、脚本库、网页桥接、API/其他；不得把无法还原的旧来源猜成某个页面。

工作流内部节点沿用节点记录，关联父 executionId；若子调用有独立底层任务，以 parentExecutionId 关联，默认列表只显示顶层。快捷卡片和其底层运行共享一个顶层 executionId，不能重复展示。

表格列为名称/ID、类型、来源、状态、开始时间、耗时、详情。支持名称/目标/ID 检索以及类型、来源、状态、时间区间 AND 筛选。记录排序使用不可变 acceptedAt + id 降序，而非可能为空或更新的 startedAt；时间筛选也按 acceptedAt，并明确显示“提交时间范围”。每页 50 条游标分页，新记录提示刷新，避免打乱阅读位置。时区按用户本地展示，接口统一 UTC。

详情包含提交时名称与分组路径、目标/环境、版本/契约、脱敏参数与引用、时间线、输出/错误、子任务与底层详情入口。开始时间尚未产生时显示未开始，耗时仅在 startedAt 后计算。窄屏表格内部滚动，页面不横向溢出。

### 8.2 接收、派发和状态落库

新统一记录是可持久追踪的执行登记，底层引擎仍决定实际执行状态。采用同数据库事务的执行登记与 outbox 派发意图；工作流/脚本底层任务创建与 executionId 关联可在同事务完成。事务成功之前不得执行外部动作；登记存储不可用时拒绝启动，而不是先执行再丢历史。

浏览器网关需接收统一 executionId 和父上下文，在外部调用前创建稳定 `bridgeCallId`，写入派发状态；底层 ID 在整个生命周期不变，完成后不得另外生成不可关联的历史 ID。服务端向外部调用传稳定 requestId；统一索引保存 `(underlyingKind, underlyingId)` 唯一映射。

outbox worker 使用原子领取及持久派发标记，派发前记录状态。排队且确定未派发、输入可完整恢复的任务可恢复领取；已派发后崩溃/超时，先按稳定 ID 查询底层，不盲目重发。外部无法查询/不支持幂等时记为待确认。凡依赖内存中的已解析引用或敏感输入的任务，重启后均不能重新解析并自动执行，按已中断/待确认处理；只有输入可从安全固定快照完整恢复、且确定未派发的任务才可恢复领取。

终态事件使用 executionId + 单调序号幂等落库，重复事件不生成新记录、不回退终态。对账器根据底层 ID 补齐关联与终态；进程存活时终态写入失败可重试写入，但绝不重跑业务动作。若进程同时丢失无查询能力的外部结果，记录待确认而不是伪造失败/成功。工作流节点、实时推送与统一详情使用一致隐私策略。

### 8.3 历史迁移与保留

现有浏览器文件历史只保留 500 条且在结束时写入，不能继续充当新执行的完整记录。切换后所有新调用先进入上述登记流程；旧工具历史页面转而查询统一记录中的浏览器执行，必要兼容响应由适配层生成，停止对新记录使用 500 条截断。

迁移时短暂停止新调用接收，完成旧数据快照与幂等导入后切换读取/写入路径。保留旧文件只读作为审核恢复材料，不双写生成第二套 ID。工作流、脚本旧记录按原底层 ID 导入；浏览器按原历史 ID 导入，只迁移仍存在的数据。已被旧 500 条策略丢弃的数据无法恢复，明确告知迁移范围。

旧记录无法证明父子关系、来源或版本时标记未知/历史未记录，不以当前配置补造，也不按名称和时间猜测去重。已知关联按稳定 ID 合并。缺失时间只可用已有创建时间回退并标记，不能用迁移时刻冒充运行时刻。

统一摘要、快照与状态默认长期保存；删除卡片、分组或目标不级联删除。已有脚本/产物清理需识别统一记录引用：可以按已确认策略清理输出，但保留摘要和来源，详情显示“输出已清理”。无输出产物的旧浏览器记录显示“历史未记录输出”。不能借旧历史文件轮转删除新统一摘要。

结构、版本候选、回填和恢复方案见 [数据库审核稿](./database-review.md)，交付顺序见 [实施任务](./coding-tasks.md)。具体 SQL、容量评估及发布审核证据后续单独准备；此处列出影响不等于授权执行迁移。环境允许名单存于现有本机设置机制，具体存储路径与校验协议随实施设计确认，不自动同步或导出。

### 9.2 拟新增接口

所有写请求执行现有本地访问保护、严格输入校验；revision 冲突返回 409。创建、复制、分组修改/删除及启动使用 requestId。接口不得回显解析后的秘密值。

| 接口 | 行为 |
| --- | --- |
| `GET /api/quick-launches` | q、field、groupId、includeDescendants、type、availability、sort、cursor、limit；返回 items、total、nextCursor |
| `POST /api/quick-launches` | 校验完整 target、手动输入与引用后创建 |
| `GET/PATCH/DELETE /api/quick-launches/:id` | 详情、带 revision 更新、只删除配置 |
| `POST /api/quick-launches/:id/copy` | 复制安全配置并生成新 ID |
| `GET/POST /api/quick-launch-groups` | 分组树/创建 |
| `PATCH /api/quick-launch-groups/:id` | revision、name、parentId，事务校验与更新 |
| `POST /api/quick-launch-groups/:id/deletion-preview` | 返回子树/卡片数、迁移选项及预览 token |
| `DELETE /api/quick-launch-groups/:id` | 预览 token、destinationGroupId（null 为未分组）、requestId，原子迁移删除 |
| `GET /api/quick-launch-targets` | 可用目标、固定版本、输入契约、执行能力和环境选项；不含秘密值 |
| `GET /api/input-source-options` | 允许引用的名称/类型/可用性；字典沿用已有列表接口 |
| `GET/PUT /api/input-source-settings` | 环境允许名单与 revision；不提供读取真实变量值的接口 |
| `POST /api/quick-launches/:id/confirmation` | 必要时生成第 4 节确认 token，无业务执行 |
| `POST /api/quick-launches/:id/executions` | requestId、revision、confirmationToken?；返回 executionId、status、详情地址；有效请求的前置失败也返回已登记记录 |
| `GET /api/executions` | q、type、source、status、from、to、cursor、limit；返回顶层记录及总数 |
| `GET /api/executions/:id` | 安全详情、子任务与底层链接、取消能力 |
| `POST /api/executions/:id/cancel` | 按底层能力转发，不将无能力或待确认任务伪装为已取消 |
| `POST /api/executions/:id/end-tracking` | 仅待确认记录，明确告知结果未知且不会撤销动作，确认后结束追踪并释放占用，记录操作时间与原因 |

“结束追踪”持久终态为 `unresolved_closed`，页面显示“已结束追踪（结果未知）”，不得映射为成功或已取消。API 旧 `/api/runs` 保持工作流协议，新页面使用 `/api/executions`；已有底层详情链接不变。底层三类调用入口均传入统一追踪上下文，不能只给快捷入口建记录。

## 10. 验收与后续实施边界

### 10.1 产品与交互验收

- 同一目标不同参数卡片分别执行；固定版本不随发布变化；编辑/删除不改变已提交快照。
- 树检索保留祖先；折叠不选中；组合筛选、URL 恢复、空结果与未分组正确。
- 分组新建/移动/重命名满足唯一性和 5 层限制；删除预览并发失效时重新确认；取消不变更数据。
- 输入框右侧引用图标、两栏检索、类型禁用、解绑、更换和键盘取消与已审核原型一致。
- 合法 JSON-only Schema 可执行；缺失/非法定义阻止启用；两种录入方式不丢值，敏感存储限制独立提示。
- 主题、长名称/JSON、390px 窄屏、键盘焦点、弹窗堆叠与状态文本检查通过；主要操作稳定可达。

### 10.2 执行与数据验收

- 浏览器多环境显式绑定，环境/契约变更后阻止启动；HTTP 不误报浏览器离线；需确认工具不能绕过服务端 token。
- 双击、跨标签页、超时重试只返回一个 executionId；请求碰撞、配置变化、未知外部结果按第 7 节处理，不重复派发。
- 接收前存储失败不执行；派发前/后崩溃、终态写入失败、重复事件、对账和无查询外部调用均有故障注入验证。
- 浏览器执行开始即有记录，超过 500 条仍可分页查询；旧历史导入可重复运行且不重复，缺失信息诚实标记。
- 引用值每次接收只解析一次；重试不重新取值；环境缺失/类型错误写启动失败；敏感任务重启不自动重取后执行。
- 敏感手动输入在持久化前拒绝；配置详情、复制、快照、回执、事件、输出、日志、产物及底层详情无秘密明文泄露。
- 删除配置/目标后历史保留，输出清理不删除摘要，父子关联及快捷/底层去重正确。
- 完成类型检查、相关交互与集成测试，再进行实际页面检查；未经验证的项明确记录，不将模拟结果当集成验收。

### 10.3 当前交付状态

原型已获用户审核通过，包含紧凑卡片、树形检索、分组管理、双模式输入和引用图标、统一记录演示及简化文案。原型仅会话内存，刷新复位；没有真实执行、来源读取或数据库操作。

原型尚未展示/验证真实浏览器环境枚举与确认 token、JSON-only 全类型支持、完整敏感策略、服务端并发与持久化、分页/取消/待确认处置、历史导入和故障恢复。这些是本方案规定的正式实现任务，不应倒推为已经通过运行验收。

后续顺序：准备数据库与适配契约审核材料 → 审核通过并获实施授权 → 公共参数/敏感策略与执行追踪 → 三类服务接入及旧历史迁移 → 卡片/分组 API 与页面 → 集成、故障和视觉验收。实际数据目录迁移以单独确认的预览为准。
