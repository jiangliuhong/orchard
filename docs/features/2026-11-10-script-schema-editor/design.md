# 脚本 Schema 可视化编辑、Agent 协同与字典参数测试

状态：已按用户确认实施；实现与验证记录见 [implementation-status.md](./implementation-status.md)

日期：2026-11-10

## 1. 目标与范围

将脚本库的「输入 Schema」「输出 Schema」从仅支持 JSON 文本编辑，升级为可视化字段编辑，常用结构无需手写 JSON。保留 JSON 高级模式，兼容已有脚本、Agent 提案和复杂 Schema。

本 feature 覆盖 **Schema 定义 → Agent 对话维护 → 参数填写／字典引用 → 测试与历史复用** 的完整闭环。交互与浏览器桥接保持一致，但沿用脚本自身的执行、版本与敏感数据边界，不照搬桥接传输协议。

包含：

- 输入、输出共用的 Schema 字段树编辑器。
- 根类型、字段名称／类型／说明／必填及常用约束编辑。
- 嵌套对象、同构数组、原始类型及布尔 Schema。
- 可视化与 JSON 模式切换、能力检测、无损兼容。
- 草稿保存、发布版本只读查看、版本切换及 Agent 应用后的正确同步。
- Agent 同步维护输入／输出 Schema 与脚本实现，差异审阅后原子应用。
- 按 Schema 生成测试参数表单，支持手动值与普通／加密字典引用。
- 测试历史恢复参数来源、执行时解析字典、敏感数据保护与安全测试上下文。

不包含：

- 自动修改源码或根据源码推导 Schema。
- 运行脚本来推断返回结构。
- 完整 JSON Schema 设计器、组合 Schema／引用的可视化编排。
- 工作流、浏览器桥接工具定义的同步改造。
- 数据库表结构、脚本执行协议和版本语义变更；测试 API 允许向后兼容扩展。

## 2. 当前实现与复用边界

- `src/web/features/ScriptPages.tsx`：脚本配置以两个 Textarea 编辑 Schema，保存时 JSON.parse，提交现有草稿 PATCH。
- `src/domain/scripts.ts`：`ScriptDefinition.inputSchema/outputSchema` 为既有契约，`validateScript` 校验 Schema 合法性。
- `src/domain/validation.ts`：采用 Ajv strict 校验，并注册 `x-ui`、`x-history`；编辑器不得另定义一套宽松的 Schema 合法性。
- `src/runtime/script-tests.ts`、`src/runtime/runner.ts`：执行前后已有输入／输出校验，本次保持不变。
- `src/web/features/BridgeParameterInputs.tsx`：浏览器桥接已有基于 Schema 的参数填写表单，可借鉴紧凑字段布局、类型提示与就地错误，但它是“填写参数值”，不是“编辑 Schema”，不能直接作为本编辑器使用。

最终仍只保存标准 JSON Schema，不引入独立的字段定义格式，也不把 UI 行 ID、折叠状态、选择状态写入脚本元数据。

## 3. 界面设计

### 3.1 工作区

保持当前脚本工作区及顶部「保存修改／发布版本」操作位置。在配置区域将输入、输出分为两个独立 Schema 编辑区，每区有稳定工具栏：

- 标题：输入参数／返回结果。
- 模式：字段编辑／JSON。
- 根类型选择、添加字段（仅 object）、更多操作。
- 显示不限制／禁止任何值／复杂 Schema 等文字状态。

桌面使用紧凑字段树列表，不增加多层卡片。字段列为：字段名、类型、必填、说明摘要、操作。选中行后在就近详情区域编辑约束；嵌套对象展开子行，数组展开“元素”节点。窄屏隐藏说明摘要并改为详情编辑，不能遮挡保存与删除操作。

### 3.2 根节点

根 Schema 不强制为对象：

- `true`：不限制结构。现有新脚本保持此默认，不静默收紧。
- `false`：禁止任何值。保留其真实语义，不作为“无参数”。
- object、array、string、number、integer、boolean、null。

“无参数对象”应显式使用 `{ type: "object", properties: {}, additionalProperties: false }`，与 `true` 区分。将 `true` 切换为对象或其他类型时视为明确契约变更，进入 dirty 状态。

根和字段提供 title、description；字段说明使用 description，字段显示名称使用 title。属性名不限制为 JavaScript 标识符，支持中文、空格、斜杠等 JSON 合法键名；内部定位必须正确转义 JSON Pointer。

### 3.3 字段操作

- 添加、重命名、删除字段；必填复选框仅出现在对象的属性行。
- 重命名同时维护父节点 properties 和 required，不影响其他字段；同级重复键阻止提交，不能覆盖原字段。
- 删除同时移除对应 required 项；含子字段或额外约束时需要确认。
- 类型切换若会删除子树或不兼容约束，预览受影响内容并确认；取消后不修改原 Schema。
- 采用稳定的临时节点 ID 保持焦点，重命名不重建输入框；该 ID 不持久化。
- 第一版不提供拖拽排序，避免暗示对象属性顺序属于运行契约。

### 3.4 常用约束

| 类型 | 可视化编辑能力 |
| --- | --- |
| object | properties、required、additionalProperties（布尔） |
| array | 单个 items Schema、minItems、maxItems、uniqueItems |
| string | enum、minLength、maxLength、pattern |
| number / integer | enum、minimum、maximum |
| boolean / null | 类型、标题、说明 |
| 所有支持节点 | true / false Schema；合法 JSON 的 default（可选高级项） |

枚举逐项编辑并保留真实类型，不能把数字、布尔值转换为字符串；默认值不代表必填，也不自动注入脚本输入。约束缺省与显式 false／0／空字符串须区分。对象的 additionalProperties 未声明时显示“允许（默认）”，不得在打开或保存时补成 false。对象型 additionalProperties、元组数组及其他复杂结构进入 JSON 模式。

## 4. JSON 模式与无损兼容

### 4.1 原则

原始 Schema 是唯一业务事实来源；字段树只是一种编辑视图。禁止通过“只保留支持字段”的重建方式转换 Schema。

使用保守的递归能力检测：只有整个 Schema 均能被当前字段编辑器完整表示时，才允许可视化编辑。包含不支持的关键词、形态或跨字段依赖时，整个输入或输出编辑区回退到 JSON，不影响另一区。

例如 oneOf、anyOf、allOf、$ref、$defs／definitions、联合类型、条件 Schema、patternProperties、对象型 additionalProperties、元组 items、required 包含未声明属性等，第一版均使用 JSON。`x-ui`、`x-history` 的现有合法形态纳入可视化能力：字符串字段可配置输入框／多行文本、占位及行数；各节点可配置“允许记录手动值”。扩展结构超出既有校验规则时不得擅自接受。能力检测不等于判断 Schema 非法。

### 4.2 模式切换

- 打开支持的 Schema：默认字段编辑；不支持的 Schema：默认 JSON，并说明阻碍可视化的路径和原因。
- 字段 → JSON：显示当前完整 Schema；切换本身不标脏，不调用保存。
- JSON → 字段：先解析、执行现有严格 Schema 校验，再做可表示性检测；失败时留在 JSON，保留原文本。
- 支持的 Schema 经过往返转换后，语义及所有键值保持一致；不得自动添加 properties、required、additionalProperties 或删除空集合。
- 不提供“一键简化复杂 Schema”，避免静默扩大／缩小契约。
- JSON 中重复对象键须在进入字段模式或保存前报错，避免 JSON.parse 后悄悄覆盖定义；实现需采用能检测重复键的解析方案。

非法 JSON 文本作为本地编辑状态保留，但不能保存或切换到字段模式；离开页面沿用未保存提醒。

## 5. 状态、校验与保存

建议单个编辑区维护：当前完整 Schema、JSON 编辑缓冲、当前模式、能力诊断、字段本地草稿／错误、会话内 UI 状态。

- 字段输入可暂时为空或无效，错误就地显示；有未解决错误时禁止整体保存，不丢失文本。
- 使用结构化路径更新 Schema，不能使用动态表达式或不安全的对象原型赋值；`__proto__` 等键必须作为普通 JSON 属性安全处理。
- 校验包含重复属性、空名称的明确策略（第一版不允许新建空名称，已有空名称转 JSON）、约束类型、非负长度、上下限顺序、枚举类型及 default 类型。
- 前端复用或抽取现有 Schema 合法性校验接口；后端 `validateScript` 仍是最终权威，不改变其边界。
- 每次有效的结构／字段变更标记整体 dirty；无效本地修改同样触发离开提醒。仅展开、选中或切换显示模式不标 dirty。
- 保留现有 expectedRevision、expectedDraftVersionId、requestId 和冲突行为。冲突时保留本地编辑，不自动覆盖服务器内容。
- 保存仍提交完整 inputSchema/outputSchema，不新增单独保存入口；保存成功后跟随服务器版本重新加载。
- 发布版本／归档脚本只读：允许展开和切换查看模式，禁止任何修改与类型转换。
- 切换版本、放弃修改、还原或应用 Agent 提案后，以新的脚本版本／修订重置编辑器；不要因普通父组件重渲染清空本地编辑。

## 6. Shell 输出协议

输入／输出 Schema 编辑器不改变实际返回协议：

- Node.js：默认导出函数接收 input，返回 JSON 可序列化值。
- Shell process：实际返回 `{ stdout: string, stderr: string, exitCode: number }`。
- Shell json：业务结果写入 `$ORCHARD_RESULT_FILE`，stdout/stderr 为日志。

process 模式的输出区显示固定协议说明，并提供“使用进程输出结构”显式模板操作；模板约束只包含真实返回字段，但不在页面初始化时自动覆盖已有 Schema。应用模板或切换协议不静默修改 Schema；需要明确提示用户核对返回定义。模板替换非默认 Schema 时预览并确认，发布版本不能应用模板。

## 10. Agent 对话协同维护

### 10.1 一致的编辑入口

- 手工字段编辑、JSON 编辑与 Agent 提案均维护同一套 inputSchema/outputSchema，不新增 Agent 专用字段格式。
- 更新 `src/authoring/script-agent-prompt.ts`：明确字段编辑支持范围、x-ui／x-history、测试字典引用与执行协议。优先生成可视化可表示的 Schema；业务确需复杂 Schema 时允许生成并解释原因，不为迁就 UI 降低约束。
- Agent 修改参数或结果结构时，需同步审视源码、Schema 和建议测试输入；提案摘要分别说明契约与实现变化。不能只改 UI 或声称已经执行测试。
- Agent 可维护 Schema 中的历史策略，但放宽 x-history.record 必须在提案差异中突出提示，默认不因字段名称猜测敏感性。

### 10.2 审阅与应用

继续使用现有 metadata、源码 changes、修订检查与确认应用流程；Schema 差异同时提供字段级摘要和完整 JSON 差异。源码与元数据作为一个提案原子应用，不自动保存、发布或执行。

存在未保存或无效的本地编辑时，不允许对旧快照发起生成或应用；用户先保存或放弃，不静默丢弃编辑。生成后草稿修订变化，提案标记过期，不自动合并。应用成功后重建 Schema 视图、重新检测表单能力，并保留现有“建议测试输入需用户确认后使用”的行为。

### 10.3 安全上下文

- 可发送给 Agent：当前已保存源码／Schema、字典名称／ID／键等必要引用元信息、用户明确选择的脱敏测试上下文。
- 不可发送：字典解密值、禁止记录的手动参数、敏感执行的输入／输出／日志。前端隐藏并不足够，服务端构建上下文时也必须过滤。
- “使用建议输入”只填入普通值，不自动选择加密字典，不将引用显示 token 当作业务参数；仍需用户确认来源后手动测试。
- 对话记录、生成请求快照、提案持久化和错误信息均遵守同一脱敏边界。

## 11. 测试参数表单与字典引用

### 11.1 与浏览器桥接对齐的交互

参考 `BridgeParameterInputs.tsx`、`BridgeCredentialInputs.tsx`、`BridgeExecutionHistory.tsx`：

- 按 Schema 展示名称／说明／必填、类型控件、枚举选择和就地校验；x-ui 控制字符串多行等展示。
- 每个可绑定参数支持“手动填写／引入字典”；字典图标打开可搜索的字典／Key 双栏选择器，只展示名称、类型、状态，不展示真实值。
- 选择后显示只读引用 `{{dictionary:dictionaryId:key}}`，点击可重选，解除引用后恢复手工输入。该 token 仅为 UI 展示，后端只接受结构化引用，不做字符串插值。
- 支持普通和加密字典；不可用／禁用字典或不存在的 Key 显示具体错误，不静默回退为空值。
- 历史点击“载入参数并前往测试”只恢复来源，不自动执行；字典引用保留并在下一次测试重新解析，未记录的手动值提示补填。
- 表单与完整 JSON 输入互斥切换，不同时铺开；字典选择、引用显示和解除操作放在表单的对应参数旁，不再单独展示来源列表。JSON 模式保留已有引用并仅提示绑定仍生效，修改引用需切回表单。
- 只要能静态识别顶层属性就允许进入表单；联合类型、缺少 type 等无法使用专用控件的字段以单字段 JSON 输入兜底，不禁用整个表单。额外输入字段在往返切换时保留。非法 JSON 或非对象输入阻止本次切换并提示原因，不静默覆盖原值。无法可靠识别属性的复杂根 Schema 仍可手动测试，不擅自简化契约。

桥接当前字典控件主要面向字符串凭据，脚本参数还包含数字、对象与数组：抽取公共选择器时按目标类型筛选，不把脚本参数全部降为字符串，也不改变桥接原有字符串限制。

### 11.2 来源模型与 API 草案

测试参数来源是“本次调用配置”，不写入 Schema default，也不混入脚本版本的 dictionaryBindings。后者是供代码通过 ctx 读取的依赖声明，两者分开展示。

建议扩展现有测试提交请求：

```json
{
  "draftRevision": 3,
  "input": { "query": "example" },
  "inputSources": {
    "/token": { "source": "dictionary", "dictionaryId": "52b517d4-e6db-43a9-9db8-3d184cddda8e", "key": "token" }
  },
  "requestId": "..."
}
```

首版 inputSources 的键仅允许指向顶层对象参数的 JSON Pointer（例如 `/token`，属性名按 RFC 6901 转义），每个引用读取整个字典 Key。根引用、嵌套目标、数组元素和从字典值中取子路径均不在首版范围，API 明确拒绝，不仅由 UI 隐藏。非对象根 Schema 仍可手动测试，但不支持字典引用。

未被引用覆盖的字段使用 input 内的手动值。新客户端提交时移除引用目标的手动副本；服务端也按引用优先处理且不得记录被遮蔽值。

- 禁止无效路径、未知参数或通过路径构造新结构；给出可定位错误。首版引用目标必须是 inputSchema 明确声明的顶层属性，复杂 Schema 无法静态识别目标时只允许手动输入。
- 引用解析后按原 JSON 类型赋值，不作隐式数值／布尔转换，再校验完整 inputSchema。整个对象或数组值可以绑定给一个顶层参数，不等于支持其内部路径绑定。
- 字典真实值只由服务端解析。前端类型提示基于键元数据，不能代替实际值校验。
- 未传 inputSources 时兼容现有 input；禁止通过用户 input 内部保留标记识别新的执行配置。

该协议为设计草案，实施时统一请求校验、类型、客户端与历史读取；不得只增加 UI 而让测试仍收到引用 token。

### 11.3 入队、快照与执行

- 入队时固定脚本版本／草稿快照和本次引用的字典版本；同时合并脚本代码依赖与测试输入依赖，纳入既有测试字典版本绑定与 GC 保护。
- 入队后修改字典不影响已排队测试。历史复用创建新测试时重新选择当时的当前字典版本，并显示本次固定版本。
- 真正执行前在服务端解析固定版本并校验完整输入；缺键、解密失败、类型／Schema 不匹配均失败且不运行脚本，错误不包含实际值。
- 服务重启沿用现有中断策略，不重放已中断测试。需要补填的手动敏感值只驻留内存，丢失后不得假装可恢复执行。
- 复用既有 input_ref／产物保存“安全参数快照＋来源＋脚本快照”；内部 envelope 版本化，兼容旧测试读取。不得把解析后的加密值写进 input_ref、命令幂等回执或队列元数据。

### 11.4 历史策略与敏感边界

沿用浏览器桥接 `history-policy.ts` 的 x-history.record 语义及父子路径优先规则；字典来源只记录引用，不记录解析值。可视化 Schema 编辑器提供该开关和清晰说明。

对齐浏览器桥接普通参数：手动值默认记录，显式 `x-history.record: false` 才禁止记录；父子节点与组合分支沿用现有保守规则，父级禁止不能被子级允许覆盖。允许记录的普通值可恢复，禁止记录的值只保留缺失标记。字典始终只记录引用，不受“允许记录”开关影响。旧历史不批量重写，缺少完整来源信息时明确标识；历史策略是记录控制，不等于加密存储。

禁止记录的手动值仅存于当前进程内存，与安全快照分离；重启后沿用测试中断策略，不恢复或自动重放，重试时用户必须重新填写。内存队列与执行交接必须保证禁止记录值不会进入现有 prepareReference(input) 持久化路径。

**脚本是任意代码，不能照搬桥接响应筛选后的安全假设。** 引用加密字典或包含禁止记录的手动参数时，整次脚本测试按敏感执行处理：输入、输出、stdout、stderr、错误详情以及 Agent 测试上下文不得持久化真实内容，沿用／加强当前敏感测试隐藏机制，不能仅靠字符串替换防泄漏。UI 明确提示将无法查看业务结果与日志；需调试时使用非敏感样例，不提供取消保护的快捷开关。

幂等请求指纹须覆盖来源、脚本修订与手动输入差异，但不得在回执保存真实敏感输入；采用不可逆且适合敏感输入的 keyed 摘要方案，避免低熵凭据可被离线枚举。取消、清理、重启及失败路径都要清除内存敏感值。

### 11.5 运行参数与结果分栏（用户确认）

右侧工作区采用同级「运行参数／运行结果／引用」三个 Tab，不将参数表单、历史列表与结果纵向堆叠。

- 运行参数：参数表单与 JSON 切换、内联字典引用；内容独立滚动，底部固定运行按钮。切换 Tab 不卸载参数编辑器，保留已填写内容及未完成的字段编辑。
- 运行结果：顶部固定历史选择与分页，其下显示状态、耗时和取消操作；主体独占剩余高度，默认显示业务输出。输入／参数复用、stdout、stderr 与字典版本信息折叠查看。
- 业务输出不设置单独的小高度上限，与折叠详情共用结果主滚动区；长行换行，不产生多层 JSON 竖向滚动框。
- 提交被服务端接受后切到结果 Tab，提交失败留在参数 Tab；轮询不因切换而中断。
- 载入历史参数后切回参数 Tab，不自动执行；Agent 建议输入同样回到参数页待确认。
- 三个 Tab 支持左右方向键、Home／End 和清晰焦点；参数／结果共享状态由独立的 ScriptRunInspector 管理。

## 12. 新增验收要求

- Agent 修改源码与输入／输出 Schema 后，差异完整、确认后原子应用，字段视图同步；过期提案及本地未保存编辑不会互相覆盖。
- 字段表单与可识别顶层属性的高级模式均可提交字典引用；覆盖普通／加密字典、顶层参数的原始类型、整个对象／数组值、键缺失、禁用及类型不符。根引用、嵌套目标、数组元素、子值 pointer 和无法识别的复杂目标必须明确拒绝。
- 队列固定版本、历史复用重新解析、旧请求／旧历史兼容、取消／重启、幂等与 GC 引用保护均有后端测试。
- 历史仅保存允许的手动值与引用；禁止记录值须补填，不得以占位当作实际参数执行。
- 用可辨识的测试 secret 扫描数据库、产物、回执、日志、对话和 Provider 请求，确认没有泄漏；包含脚本主动输出 secret 和异常抛出 secret 的负向用例。
- 浏览器实际检查对齐桥接的选择、重选、解除引用、历史载入及键盘交互，并覆盖深浅色与窄屏。

## 13. 评审确认与开工门槛

用户已确认以下五项产品决策：

1. 普通手动参数默认记录历史，显式禁止才不记录；字典仅记录引用。
2. 加密字典或禁止记录的手动参数使整次测试进入敏感执行，只展示状态、耗时与安全错误，不提供明文结果／日志查看开关。
3. 首版字典能力收敛为顶层参数引用整个 Key，保留 JSON 类型，不支持复杂路径。
4. Agent 仅产出提案，源码与 Schema 经确认原子应用，不自动保存、发布或测试；本地未保存和过期提案不能相互覆盖。
5. 禁止记录的手动值只驻留内存，重启后中断，重试重新填写，不新增持久化凭据机制。

核心产品决策已闭合，用户已明确确认“开始编码”。该确认不等于数据库结构变更授权。实现中若发现能力边界无法成立或必须改表，应暂停相关部分重新评审。

技术落地检查不再作为用户产品问题：由实施者通过测试验证现有队列、引用产物、字典版本绑定、幂等摘要、Agent 上下文与历史读取的安全路径，并在实现中补齐。现有“输入先持久化再由读取接口隐藏”的行为不能作为新敏感参数的实现方案。
