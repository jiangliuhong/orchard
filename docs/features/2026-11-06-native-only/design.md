# Agent 仅支持原生协议

状态：已完成，数据库变更已获用户审核通过。
日期：2026-11-06。

## 目标与范围

删除 Agent 的 legacy 传输模式及一次性 CLI 执行实现，Codex 使用 app-server，Pi 使用 RPC。保留原生协议的独立单次调用和多轮会话。升级后新建、继续、模型验证和工作流节点执行均不能进入旧调用路径。

用户在设置中配置可执行文件和模型，无需选择传输模式。原生协议探测失败时明确报错，不回退。保留历史消息、轮次、运行和工作流数据。

本次不删除与 Agent 传输无关的旧数据兼容逻辑，不篡改历史设计记录。旧版本迁移 SQL 中的 legacy 字面量仅用于识别升级输入，不构成运行时支持。

## 数据库审核方案

原数据库版本为 6，本次增加 v6 → v7 迁移，更新新建数据库定义。用户已确认数据库约束及数据迁移方案，授权实施。

重建 `agent_conversations` 表，保留全部列、主键、外键、现有索引和归档约束，仅修改以下约束：

```sql
context_mode TEXT NOT NULL CHECK(context_mode IN ('isolated','native')),
transport TEXT NOT NULL CHECK(transport = 'native'),
CHECK (
  (mode='single' AND context_mode='isolated')
  OR (mode='multi' AND context_mode='native')
)
```

迁移数据规则：

| 数据 | 迁移处理 |
| --- | --- |
| 已有 native 对话 | 保留配置与会话记录，由现有启动恢复机制处理连接 |
| 旧传输的单次对话 | transport 设为 native，context_mode 保持 isolated；清空后端引用、同步修订和连接指纹，使新请求使用新连接 |
| 旧传输的多轮对话 | transport 设为 native，context_mode 设为 native；清空后端引用、同步修订和连接指纹，非归档状态设为 needs_rebuild，归档状态保留 |
| 所有旧传输对话 | backend_generation 递增，使旧连接代次失效；保留 ID、消息关联、标题、模型、创建时间和历史记录 |
| 内置 Codex/Pi Provider 配置 | transport 统一写为 native，保留其余配置；配置 revision 递增，避免继续使用旧配置快照 |

归档旧多轮对话恢复时必须进入需要重建的状态，不允许因已转换字段而冒充已存在原生上下文。重建会创建新的原生会话，并仅在首轮携带受限历史摘录。旧单次对话允许通过新建会话继续，旧连接指纹不能被复用。

迁移复用现有升级前备份、事务、行数和外键校验，重建后恢复 `one_current_conversation`、`conversations_by_draft`、`conversations_by_activity` 三个索引。失败回滚，不自动启动原生连接。升级后旧版本程序不可直接打开 v7 数据库；需要回退时恢复升级前备份与对应程序。

## 代码和接口影响

- 内置 Provider 默认并仅接受原生协议，移除兼容模式选择器和旧 CLI 执行解析代码。
- readiness、会话和持久化类型移除 legacy 枚举，移除 reconstructed 上下文模式和自动历史拼接分支。
- 保留显式重建上下文能力；历史摘录来源仅表示显式重建。
- 不支持原生会话的 Provider 调用明确失败；测试替身按原生会话接口更新。
- 设置、会话状态、连接指纹、启动恢复及归档恢复规则保持一致。
- 更新产品和 Provider Wiki，替换旧传输回归测试为原生调用及拒绝旧配置测试。
- 工作区已有未提交的前端和脚本库改动，实施时保留这些改动并在其基础上修改。

## 验收标准

1. 全新安装默认使用原生协议，设置页面不存在兼容模式选项。
2. API 拒绝显式 legacy 配置，原生探测失败不会启动旧 CLI 命令。
3. Codex/Pi 的节点执行、模型验证、单次和多轮创作均走原生接口，单次上下文保持隔离。
4. v6 数据升级后满足新约束；旧版本顺序升级仍可用；所有原有表行数、消息和外键完整。
5. 旧多轮对话必须重建后继续；归档恢复不能绕过重建要求。
6. 覆盖迁移失败回滚、备份、原生连接失败、取消和上下文重建；运行类型检查和相关测试。

## 审核结论

用户在本会话明确回复“确认”，批准上述数据库约束及数据迁移规则。与显式数据迁移功能合并后，已批准的 v6 → v7 SQL 注册到迁移向导，在用户预览和确认后执行；Store 只打开已经就绪的当前数据库。开发验证使用临时数据库，不直接操作用户的运行中数据库。
