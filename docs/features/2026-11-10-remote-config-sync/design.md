# 从远端同步配置

状态：用户已于 2026-11-10 确认范围，编码完成；621 项自动化测试、类型检查、发布完整性检查及构建通过。实际页面视觉和两台物理电脑人工验收未完成，详见 [implementation.md](./implementation.md)。

## 已确认的范围扩展（优先于初始规划）

本期交付目标是跨电脑配置迁移与执行闭环，而非仅增加恢复 UI：

- 普通字典与加密字典均支持备份到 Git、从 Git 恢复；密钥始终独立迁移、不进入 Git。
- 同步保留本机独有对象；同 ID 字典按源版本完整键集更新，移除键须预览；同名不同 ID、kind 不一致、同版本 ID 内容不同均阻止应用。
- 本机缺密钥或认证失败时阻止相关字典应用，不开放“仅导入密文”模式；无相关依赖的其他类别仍可独立同步。
- 实现工作流普通字典输入绑定、内嵌代码/Shell 及固定脚本版本的字典声明、入队版本固定、上下文注入和敏感执行保护。
- 备份必须携带字典依赖，恢复不能跳过依赖后宣称可执行；沿用获取时固定 SHA。
- “直接执行”允许先完成独立密钥导入、Provider 登录、运行时安装和浏览器接入；之后不需要重新编辑工作流或重建字典。
- 最终验收：两个隔离实例 A 备份 → B 恢复并补齐本机接入 → 实际执行成功。

以[字典设计](../2026-11-09-dictionaries/design.md) §§4–8 的定义、执行和 Git v2 协议为基础；其中“允许仅恢复密文”由本次确认明确收窄为拒绝。复用已经审核并实施的 v9 表及绑定表，不改变既有 DDL；新增结构需求仍须另行审核。

## 1. 目标与现状

在现有“配置同步”工作区增加“从远端同步”，将绑定分支的配置快照应用到本机，形成“备份到远端 / 从远端同步”两个明确方向。

实施前基线（保留规划时现状；当前能力见实施记录）：
- `src/web/features/ConfigGitSettings.tsx` 已提供提交预览、提交并推送、操作轮询和浏览器外观回执，但没有远端恢复 UI。
- `src/config-git/repository.ts` 已有 fetch、仓库状态和按固定 SHA 读取快照；读取快照不需要 checkout。
- `src/config-git/service.ts` 已有恢复预览、类别选择、本机映射、差异分页及应用能力。
- 已有恢复点、写入协调器、幂等回执与崩溃恢复协议，继续复用，不另建导入引擎。

本功能是上述能力的产品闭环，不是 Git pull，也不是数据库全量覆盖。

## 2. 首期范围与非目标

### 首期

1. 主动获取绑定分支的最新远端提交，固定来源 SHA。
2. 选择配置类别、补充本机映射，查看实际应用差异。
3. 显式确认后应用，展示结果、恢复点及需要重新连接的服务。
4. 网络中断、刷新和服务重启后能继续查询已受理操作。
5. 提供本次同步前恢复点的预览与恢复入口。

### 不包含

- 定时同步、启动自动应用、双向自动合并。
- 删除远端没有的本地对象，或“完全以远端为准”的破坏性镜像模式。
- reset/clean/stash、丢弃未推送提交、移动本地分支、自动 commit/push。
- 任意仓库/分支切换、完整远端历史浏览器。
- 字典之外的新配置类别。当前 v1 五类别扩展为 v2 六类别，新增 dictionaries；不在快照中的配置不能宣称已同步。

## 3. 产品交互

### 3.1 入口与布局

- 左下角“配置同步”工作区内使用两个紧凑页签：“备份到远端”（保持现有功能）、“从远端同步”。设置页继续负责仓库绑定，不重复增加第二套同步界面。
- 工具栏显示仓库、分支、领先/落后、最近成功获取时间；远端操作按钮固定在工具栏。
- 切换页签不自动创建提交预览或执行网络请求；离开有映射输入/确认状态的预览时提示放弃。
- 未绑定时引导前往 Git 仓库配置；尚无远端快照时提示先在其他设备备份，不将空快照解释为清空。

### 3.2 同步流程

1. 点击“获取远端配置”：fetch 成功后固定绑定分支的远端 SHA，显示提交说明、作者、时间与短 SHA（可查看完整值）。
2. 展示可同步类别，默认勾选当前格式支持且快照中提供的类别；明确列出不在本次同步范围的配置。
3. 点击“预览同步”：服务端使用固定 SHA 生成恢复预览。类别或映射改变后旧 token 与确认状态失效，必须重新预览。
4. 按类别展示新增、更新、无变化、保留本地项及阻塞原因；当前草稿覆盖、发布指针变更、本机映射和自动补入依赖类别必须突出显示。
5. 必须加载全部差异、补齐映射、解除阻塞，并勾选“已查看差异，确认将远端配置应用到本机”，才可点击“应用到本机”。无变化时禁用应用，不创建无意义恢复点。
6. 应用期间展示阶段，禁用重复提交；用户可离开页面，但离开不代表取消已受理操作。
7. 完成后显示“已应用远端快照 <SHA>”、各类实际变更统计、恢复点和重连提示。刷新相关资源；不能宣称本地与远端完全一致。

“重新获取”会使当前预览失效。网络错误保留旧来源信息但标注过期，不允许把失败的 fetch 当作最新同步成功；首期不提供离线远端同步。

### 3.3 恢复点

成功结果提供“查看同步前配置”，进入同样的差异预览和确认流程，调用既有恢复点接口。恢复点恢复不删除已导入的不可变版本或本地独有对象，不标为完全撤销。结果区域失去后，通过既有恢复点列表重新找到该记录。

## 4. 同步语义与保护边界

- 以稳定 ID 匹配。远端独有对象新增，同 ID 对象按现有恢复规则更新；本机独有对象、历史版本和运行记录保留。
- 源发布指针或草稿为空时沿用现有保留语义，不能擅自解释为删除。覆盖草稿产生新的本机修订，旧测试通过状态不能沿用。
- 不可变版本同 ID 不同内容为硬冲突，整次应用阻止；不提供“强制覆盖”。同名不同 ID 按领域约束校验，不能按名称偷偷合并。
- 依赖缺失时明确展示自动补入的类别及原因，重新确认；不能同步部分对象后才报告失败。
- 脏 Git 工作区或进行中的 merge/rebase 等状态阻止预览与应用，列出阻塞路径，不自动修复。
- 领先或分叉本身不阻止读取远端快照：说明“本次应用远端快照，本地未推送提交仍保留；后续备份可能需要另行处理分叉”。不移动本地 HEAD，不创建新的 Git 提交。
- 认证、可执行文件路径、浏览器连接及本机密钥不从远端直接覆盖；使用现有字段策略和本机映射。敏感差异、错误与日志必须脱敏。
- 有活动运行、测试、Agent 或验证时，应用返回忙碌状态；不自动取消任务，不在后台等候后未经重新校验应用。
- 复用现有恢复点、数据库事务、文件补齐、缓存重载和维护门禁。失败后绝不靠拷贝旧数据库回滚。

### 固定来源与并发

预览绑定 bindingId、分支、sourceSha、类别、映射、目标修订和浏览器偏好版本。确认时绑定、HEAD、目标配置或偏好变化必须使预览过期。

本次操作定义为“应用获取时的固定远端快照”，不是“确认瞬间的远端最新状态”。确认前不强制再次联网检查远端，远端在其他机器新增提交不改变本次来源；UI 全程展示获取时间与 SHA。用户主动重新获取时，必须重新生成预览，不能悄悄换源。

## 5. 接口与实现边界

### 5.1 复用

- `POST /api/config-git/restore-preview`：固定 `source: { kind: "git", sha }`，提交类别、本机映射与浏览器偏好。
- 现有预览差异分页接口：确认前加载完整内容。
- `POST /api/config-git/restore`：只提交 token 和 requestId，不接受前端重新拼装导入计划。
- 现有操作状态、恢复点列表/预览、恢复重试及外观回执接口。

### 5.2 补齐远端来源获取

新增 `POST /api/config-git/remote-sync-source`（带 requestId），在 repository 的同一个排他操作内完成 fetch、读取绑定远端 ref、读取提交元数据，返回固定来源：

`{ bindingId, branch, sourceSha, fetchedAt, commit: { subject, author, committedAt }, snapshotState, supportedCategories }`

- 必须复用 fetch 内部实现；不能以几个互不关联的前端请求拼装“最新来源”，也不能在已有排他方法内递归获取同一锁。
- 远端分支不存在、无快照、快照不兼容、认证失败和网络失败分别返回可识别状态/错误。
- 网络操作沿用异步受理与操作查询协议；不持有配置写入排他窗口。
- 返回可同步类别必须来自快照校验结果，不能只根据 UI 常量猜测。
- 恢复预览补充展示所需的保留项、依赖补入原因、实际应用前后值。现有原始源/目标差异若与合并计划不一致，须修正为实际计划，不能只改变 changeType。
- 应用结果及操作恢复后均能获取 sourceSha、实际变更统计、recoveryPointId 和重连信息；根据当前持久化结果能力补充兼容字段。

实现前核对当前 routes/operations 响应形状，并补齐契约测试；不依赖前端非持久化回调识别“这次是同步还是备份”。

### 5.3 数据与审核

预期无需数据库表结构变更，复用已审核的 v9 字典、版本、运行/脚本测试绑定表，以及已有恢复回执和 Git 目录外操作记录。不得改写已审核的 SQL、协议资源和历史迁移身份。新增业务源码按仓库流程刷新未发布版本的校验封装；刷新前保留既有清单和 bundle，并核对审核身份不变。若实施时发现必须扩表、新增表或修改约束，应先单独提交结构审核并等待用户批准，再实施相关变更。

新增操作记录字段须向后兼容，旧操作仍可查询和恢复。预览 token 过期或重启丢失时重新预览；已受理应用通过持久化 requestId/operationId 找回，不因 token 失效重复执行。

## 7. 验收与测试

1. 两个隔离实例连接同一真实 Git 远端：A 备份，B 获取、预览、确认，验证配置和来源 SHA。
2. 新增、同 ID 更新、草稿覆盖、发布指针移动、本机独有项保留；重复相同快照无变化，不重复创建版本或递增修订。
3. 缺失映射、依赖补入、不可变版本冲突、无效/新版快照、无远端分支、无快照均有明确提示；任何阻塞不产生业务变更。
4. 脏仓库、领先、落后、分叉、有未推送提交分别测试；同步前后 HEAD、工作树内容及未推送提交保持不变（fetch 更新远端跟踪引用除外）。
5. 预览后本机编辑、切换绑定、类别/映射变化使旧预览失效；远端继续前进时仍应用界面展示的固定 SHA。
6. 双击、HTTP 重试、断网后重连和页面刷新不重复应用；同 requestId 不同参数被拒绝。重启丢失预览须重做，已受理应用须恢复原结果。
7. 活动任务阻止应用；数据库提交前后进程中断复用恢复测试，补齐新入口关联测试。recovery_required 不误报成功，并可重试恢复。
8. 外观偏好冲突按现有协议由用户选择；Provider/Bridge 重连提示准确；成功后相关页面数据更新。
9. 恢复点预览与应用可用，并明确其非破坏性恢复边界。
10. UI 类型检查和交互测试；实际检查浅色、深色、跟随系统、长差异、窄屏、键盘焦点及图标可访问名称。未完成视觉验证必须在交付说明中列出。
