# Git 项目工作区与 Agent 分析节点

状态：设计已于 2026-11-10 获用户确认，进入技术验证；功能尚未实施

创建日期：2026-11-10

已确认方向：SSH 密钥引用；全部项目资源放在 Orchard 数据目录内；设置增加存储查看；Pi、Codex 均验证项目分析，不新增 Agent 只读工具或项目沙箱；不新增仓库存储配额。用户接受本机 Agent 操作风险。Orchard 不主动 push，但不保证 Agent 无法自行 push。数据库结构变更仍须另行审核。

## 1. 目标

接收问题等工作流输入，针对指定 Git 项目自动准备本机代码目录，由 Agent 在该目录内读取、搜索和分析代码，将最终结论作为节点输出，供后续节点或整个工作流结果使用。

```text
工作流输入 → 准备项目（首次 clone / 后续 fetch）
          → 固定 commit → 独立代码快照 → Agent 分析 → Schema 校验 → 节点输出
```

“已经 clone 就 pull”的产品语义为每次分析获取指定分支最新代码；实现使用 fetch + 固定 SHA，不直接 pull/merge。缓存可复用，运行目录临时且互相隔离。

## 2. 现状与设计约束

- `src/runtime/runner.ts` 已将节点输入拼入 Agent prompt，校验并持久化节点输出；顶层 `result` 可绑定节点结论。
- `src/providers/registry.ts` 的一次性调用在传入 cwd 下另建 `.agent-*` 空目录，不能直接用于项目分析。
- Pi RPC 明确使用 `--no-tools`；Codex 也禁用了多项工具特性，二者均声明 `tools: false`。不是改 cwd 就具备代码分析能力。
- `src/config-git/repository.ts` 已有 SSH、非交互 Git、超时和脱敏经验，但其业务是单仓库配置备份，不直接复用其绑定、快照限制或恢复逻辑。
- 创作对话与工作流执行是不同场景。本 feature 不改变现有创作会话的目录和工具权限。

相关资料：[流程协议](../../wiki/architecture/workflow-format.md)、[Provider](../../wiki/architecture/providers.md)、[配置 Git 设计](../2026-11-06-config-git-storage/design.md)。

## 3. 范围与非目标

### 首期

1. 本机配置多个项目，每个项目绑定一个 SSH Git 地址和默认分支。
2. 节点引用一个项目，按配置的分支读取代码；首期地址和分支不接受运行输入动态覆盖。
3. 首次下载、后续更新、固定来源 SHA、并发隔离、超时取消、异常清理。
4. 单次 Agent 任务，可使用 Provider 工具读取、搜索代码或执行命令，最终返回满足节点 Schema 的 JSON。不新增只读工具限制，沿用 Provider 本身的权限机制。
5. UI 展示项目、分支、SHA、准备阶段与失败原因。
6. 设置增加“存储空间”，查看当前 Orchard 数据目录的总占用、分类占用和项目仓库明细，支持手动刷新；首期只读查看。

### 不包含

- 多轮用户追问、跨运行继承会话、一个节点分析多个仓库。
- Orchard 主动 commit/push、PR 创建、依赖安装或测试编排。Agent 自行执行命令、修改代码不做新增强制限制，不承诺其不会执行上述操作。
- Git HTTPS、子模块递归下载、Git LFS 对象下载、任意本机目录挂载。
- 任意远端 URL、SSH 命令、绝对路径从工作流输入透传。
- Webhook/消息平台接入；沿用现有工作流运行 API 接收信息。

## 4. SSH 密钥认证

### 4.1 本机凭据档案

建议首期采用“本机预配置密钥 + Orchard 保存引用”，不在网页上传、生成、显示或托管私钥。

本机管理员创建 SSH 凭据档案：`id/name/host/port/user/identityFile/knownHostsFile/useAgent`。私钥与 known_hosts 均使用本机绝对路径，仅在管理员设置中配置；工作流只引用项目 ID，不得传入凭据参数。页面只显示档案名称和校验状态，不返回路径原文、密钥或 agent socket。

- 每项目或每组项目使用专用 SSH 身份。SSH 私钥本身没有 pull/push 权限属性；真正只读授权取决于 Git 服务端。本 feature 不要求用户修改 Git 平台配置，不宣称平台内的密钥引用能强制阻止 push。
- `identityFile` 必须为本机普通文件，拒绝符号链接和组/其他用户可读写的私钥；父目录必须受控。运行账户必须能够读取。
- 加密私钥由用户预先解锁到 Orchard 服务可访问的 ssh-agent；不采集或持久化口令。不允许无提示回退到其他密钥。
- Orchard 管理的 Git 传输指定 `IdentitiesOnly=yes` 和确定的身份；`useAgent=false` 时禁用 agent。Agent 沿用 Provider 本身的环境机制，不将 socket 隔离作为安全保证。
- 明确“本机”是运行 Orchard 服务的主机，不是浏览器所在机器。服务模式可能没有桌面终端的 agent 环境，必须独立检测。

建议固定选项：`BatchMode=yes`、`StrictHostKeyChecking=yes`、`ForwardAgent=no`、`ClearAllForwardings=yes`、`ConnectTimeout`，禁用密码和键盘交互认证。使用专用受控 SSH 配置，避免继承用户配置中的 ProxyCommand、LocalCommand 等命令；自建 Git 服务首期支持显式端口，不支持任意 SSH alias/跳板脚本。

Git 与 SSH 均使用参数数组，不使用 shell 拼接用户输入。通过受控 SSH launcher 传递固定参数；若使用 `GIT_SSH_COMMAND`，必须有专门的参数转义与注入测试，不能字符串直接插值路径或地址。

### 4.2 主机信任和检测

- 支持 `git@host:group/project.git`、`ssh://git@host:port/group/project.git`，规范化后 host/port/user 必须与凭据档案一致。拒绝控制字符、选项注入和非 SSH 协议。
- 未知主机或指纹变化阻止连接，不使用 `StrictHostKeyChecking=no`、自动 TOFU 或静默写入 known_hosts。
- 管理员通过可信渠道验证指纹并维护 known_hosts；`ssh-keyscan` 只可用于采集候选值，不作为信任证明。
- “检测连接”执行受限 `ls-remote --heads`，验证读取权限并列出分支；不验证推送权限、不创建提交。
- 错误区分：主机未信任/主机密钥变化、密钥不可用/未解锁、仓库无权限、网络超时、分支不存在。无法可靠区分的 SSH 错误给出通用认证错误，不猜测。
- 凭据档案增删改须明确用户操作；工作流执行不得自动更改主机信任或凭据。

Orchard 不主动将 SSH 私钥、known_hosts 内容、socket 或凭据参数拼入 prompt、API/SSE 日志、Git 配置备份或错误原文。Git 管理进程使用受控环境。但 Agent 可执行命令并可能访问运行账户的文件与环境，不保证凭据不可被 Agent 读取；启用项目时必须明确提示该风险。不能把界面隐藏凭据误称为 Agent 安全隔离。

## 5. 项目定义与工作流契约

### 5.1 本机项目

建议项目模型：

```ts
interface GitProject {
  id: string;
  name: string;
  remoteUrl: string; // SSH only
  branch: string;
  sshProfileId: string;
  enabled: boolean;
  revision: number;
}
```

项目 ID 在本机稳定；远端/分支/凭据变更递增修订。项目配置属于本机接入，首期不新增配置 Git 导出类别、不做跨设备自动映射。引用它的工作流跨设备导入时必须检查项目依赖；缺少匹配 ID 的有效本机项目时阻止相关工作流应用，说明原因，用户先配置匹配项目后重新预览。发布版本不可变，不能为补映射改写版本内容。

### 5.2 Agent 节点可选扩展

```json
{
  "id": "analyze",
  "name": "项目分析",
  "type": "agent",
  "input": { "source": "workflow" },
  "config": {
    "agentConfigId": "code-analysis",
    "project": { "projectId": "orchard" },
    "prompt": "根据输入问题分析代码，返回 summary 与 findings。",
    "timeoutMs": 600000
  },
  "outputSchema": {
    "type": "object",
    "required": ["summary", "findings"],
    "properties": {
      "summary": { "type": "string" },
      "findings": { "type": "array", "items": { "type": "string" } }
    },
    "additionalProperties": false
  }
}
```

没有 `project` 的节点完全保持旧行为。存在 `project` 时校验项目存在、启用以及 Provider 的项目分析能力，未知字段拒绝；旧客户端/旧服务端不可忽略新字段后继续执行。

业务输出仍由 `outputSchema` 决定，不强制注入 SHA 字段；来源信息单独记入 execution 元数据，Agent prompt 提供项目名、分支、完整 SHA，用户可要求业务输出包含来源。最终结果仍通过 `{source:"node",nodeId:"analyze",pointer:"/summary"}` 绑定。

## 6. 仓库缓存、快照与版本固定

仓库 clone 的完整缓存、clone staging、代码快照、lease 和项目 Agent 临时会话目录必须位于当前实例实际使用的 Orchard 数据目录中，不使用系统临时目录或另一个独立配置的仓库根目录。`<data-dir>` 取服务启动后解析的实际根目录（含自定义数据目录），不能硬编码 `~/.orchard`。外部 SSH 私钥仍只保存引用，不因该规则复制进数据目录。

目录约定：

```text
<data-dir>/project-git/
  projects.json                 # 本机项目定义，原子写入
  ssh-profiles.json             # 本机 SSH 引用，无私钥原文
  cache/<project-id>/<revision>/ # clone 后的受控 bare 仓库
  staging/<operation-id>/        # clone/物化暂存，失败后回收
  sessions/<run-id>/<node-id>/<attempt-id>/ # 项目 Agent 临时会话
  leases/<run-id>/<node-id>.json # 固定来源、资源与清理状态
  workspaces/<run-id>/<node-id>/<attempt-id>/ # 独立可写源码快照
```

1. 入队时固定项目 ID、修订、远端、分支与凭据引用修订，避免排队期间配置变化悄悄换仓库。敏感本机参数只存在受控内部记录。
2. 执行节点时按项目修订获取排他锁；首次 clone bare 到 staging，完整成功后原子就位；后续 fetch 指定分支到受控 ref。不使用 mirror 接收无关 refs。
3. 在同一锁内解析目标 commit，建立本次 lease 和保留 ref，再释放锁；并发 fetch/清理不能让已选 commit 丢失。SHA 在准备阶段固定，语义为“节点开始准备时获取的版本”，不是入队时版本。
4. 从固定 commit 创建独立可写源码快照。首期建议直接按 Git tree/blob 物化，不主动附带 bare 缓存的 `.git` 指针或认证配置，不触发 checkout filter、hooks、LFS smudge。这是宿主管理行为，不保证 Agent 无法自行访问缓存或运行 Git 命令。
5. 普通文件和目录按提交物化；Git submodule（独立 Git 仓库引用）不递归下载。符号链接不跟随，LFS 不下载对象，给出未展开项说明。宿主物化时拒绝路径穿越、大小写/平台路径碰撞和管理目录逃逸；不新增仓库大小、单文件大小、文件数量或磁盘配额。磁盘不足按实际 I/O 错误失败，不能静默截断后称为完整分析。
6. 快照允许 Agent 写入，不新增作用域工具或文件系统隔离。Agent 会话放在独立目录，不混入源码。宿主只清理受控目录，不承诺回滚 Agent 对目录外文件的修改。
7. 成功、失败、取消后释放会话、删除快照并释放 lease/ref；清理失败记录并重试，不能改写已经产生的业务结果。启动时先协调既有运行状态，再回收无活动持有者的资源，不删除仍被租用的目录。

不同运行不共享源码工作树；Orchard 的仓库管理不执行 pull/merge/reset/stash/push，不接管用户本地仓库。提示词要求 Agent 不主动推送，但不保证其遵守或无法推送。网络更新失败默认节点失败，不偷偷使用旧缓存；首期不提供离线降级。取消/超时沿用既有进程终止和锁释放机制，不承诺回滚命令的外部副作用。缓存长期保留，本次不新增配额、容量驱动自动 GC 或用户清理功能；运行快照在成功/失败/取消后删除，Agent 在其中的修改不保留，只保留结论与来源元数据。

## 7. Agent 执行与安全边界

采用用户信任、自担风险的本机 Agent 执行模式，不新增只读工具、项目沙箱、宿主文件访问或命令权限限制。沿用 Provider 自身的权限机制；Orchard 不能将“cwd 在独立目录”宣传为安全隔离。

- 为 Provider 增加按场景声明的 `projectAnalysis` 能力，验证能否在指定目录使用工具、执行任务并返回结构化结果，不以只读隔离作为能力门槛。
- 普通节点/创作会话保持既有策略；项目场景启用 Provider 的项目工具能力，不全局放开现有全部场景。需要调整 Pi 的 `--no-tools`，以及 Codex 的工具禁用配置和请求处理策略，不能仍按 TOOLS_DISABLED 拒绝所有工具事件。
- Pi、Codex 都必须实际验证，不以其中一个成功推断另一个可用。某个 Provider 不可用时记录原因并禁用其项目分析；至少一个通过才能交付可用的项目分析，未支持项须明确披露。
- 首期不承诺开放用户扩展、MCP 等与项目分析无关的所有功能；不额外构建受控工具桥。具体启动参数和交互请求处理以双 Provider 验证结果为准。
- Agent 可能执行命令、修改快照和宿主文件、访问网络或使用本机凭据；仓库 README、AGENTS.md 等内容也可能影响其行为。不保证拒绝越界请求，不保证阻止泄密、推送或其他副作用。
- Orchard 不提供 push 管理操作；prompt 要求不推送仅是行为指引，不是强制权限。SSH 私钥本身无只读属性，远端权限不由此 feature 控制。
- 启用项目时必须由用户明确接受本机文件/命令操作风险，并确认源码可发送给所选模型服务；风险提示不以“只读”措辞误导用户。不对 Agent 可能读取的仓库秘密承诺自动识别过滤。

`ProviderRegistry` 增加显式执行上下文：默认 `isolated` 保持现状；`project` 使用指定快照 cwd，不再在其中创建空 `.agent-*`。会话仍为一次性，使用工具直到最终输出或超时；沿用现有输出 Schema 校验、取消、usage、协议输出预算和事件机制。项目执行策略应参与会话标识/指纹，不能复用普通无工具场景连接。

## 8. UI、API 与可观测性

### UI

设置增加“项目仓库”，使用紧凑列表 + 右侧详情，管理项目、SSH 档案引用、分支、启停和连接检测。不出现私钥输入框。凭据档案只暴露安全元数据；本机配置方法在帮助中说明。

Agent 节点编辑器增加可选“项目上下文”，选择启用项目并展示分支、Provider 能力和源码发送提示。运行详情增加准备阶段、项目快照、短 SHA/完整 SHA 复制、耗时和安全错误；准备阶段属于该 Agent 节点，不新增业务节点。

启用项目须确认“Agent 可执行命令、修改本机文件并访问凭据；Orchard 不保证阻止 push；源码可能发送给模型服务”，保存确认的策略版本。没有确认不能运行，策略升级涉及风险变化时重新确认。该确认不构成沙箱或权限保证。

沿用现有主题、13px 紧凑尺度、焦点和键盘操作；长地址截断但可查看，不靠颜色单独表达状态。窄屏详情可折叠。

### 拟议 API

- `GET/POST /api/git-projects`、`PATCH /api/git-projects/:id`：本机项目管理，更新带 revision 校验。
- `POST /api/git-projects/:id/check`：异步连接/分支检测，返回 operationId。
- `GET /api/git-project-operations/:id`：查询阶段和安全结果；检测接口限并发、限频，不接受任意 SSH 参数。
- `GET /api/git-ssh-profiles`：仅返回 ID、名称、安全状态；首期档案通过本机受控配置管理。
- 删除优先采用禁用/归档语义；有草稿、发布版本、活动运行引用时拒绝物理删除。

API 必须遵守现有认证与写操作保护约定。运行执行不需要前端串联准备 API。

拟议事件：`project.preparing`、`project.fetching`、`project.ready`、`project.cleanup_failed`。payload 只含项目 ID、分支、SHA、阶段与耗时，不含绝对路径、凭据或原始 stderr。工具日志也应按现有敏感执行策略脱敏，不能因项目事件新通道泄露加密字典输入。

### 8.1 设置中的“存储空间”

此页面统计整个 Orchard 数据目录，不只是本 feature 的 Git 缓存；没有项目仓库时也可使用。

#### 展示内容

设置侧栏增加“存储空间”，沿用现有紧凑设置布局：顶部路径与摘要、刷新工具栏、分类表格、项目占用明细；不使用大面积仪表盘卡片。

- 当前服务实际数据目录的完整路径，可复制；这是受保护的设置接口特许展示，不在普通运行事件或错误中暴露服务器路径。
- Orchard 目录占用：默认显示实际分配空间，同时提供逻辑大小、文件数和统计时间。
- 所在文件系统总容量与当前运行账户可用空间；明确这是整个磁盘/卷的容量，不是 Orchard 配额，也不能把磁盘已用量当作 Orchard 占用。
- 分类占用：数据库（含 WAL/SHM）、工作流/脚本定义与产物、运行资料、Agent 工作区与会话、配置 Git 仓库及恢复资料、项目 Git 缓存、项目运行快照/临时文件、密钥与本机配置、其他。
- 项目明细：项目名/ID、各修订缓存合计、运行快照与临时文件合计、占用及当前是否有活动 lease；已删除配置留下的孤立目录仍按 ID 展示，不能漏计。
- 明确提示“本页仅查看，不会清理文件”；首期不增加删除、GC、数据库压缩或自动清理设置。

分类通过服务端受控路径规则互斥分配，数据库和项目目录先匹配，其他类别按当前目录布局核对；未识别内容统一计入“其他”，不得漏计或重复计算。设置中的路径显示不授权文件浏览、下载、读取私钥或查看任意文件名。

#### 统计口径与安全

- 服务端直接读取文件系统元数据，不运行用户提供的 `du`/shell 命令，不读取业务或密钥文件内容，不触发数据库 checkpoint/VACUUM 或 Git GC。
- 默认按 `st_blocks × 512` 计算已分配字节，另按 `st_size` 统计普通文件逻辑字节；平台不支持 allocated 指标时返回不可用并显式降级到逻辑大小，不能将两者混为同一个指标。
- 使用 lstat，不跟随符号链接；链接本身计入当前目录，链接目标不计入。内部挂载点不跨设备扫描，显示有排除项；根目录在启动时已解析，扫描中的路径替换不得越界。
- 同一设备/inode 的硬链接在整个扫描中只计一次，按稳定路径遍历确定分类归属。文件系统压缩、reflink、快照及共享块不保证可准确归属，页面说明“估算，不等同于删除后的可释放空间”。
- 扫描覆盖隐藏文件和遗留 staging；目录自身元数据纳入 allocated 统计。项目明细是分类下钻，不与顶层再相加。
- 数据目录以外的私钥、Provider 用户目录和外部备份不计入；显示统计范围说明。
- 运行中写入、文件消失、权限不足和超时允许产生部分结果，但返回 `partial`、原因计数及扫描起止时间。无法读取的内容不是 0；不存在一致性快照保证，不能标为精确实时值。
- 同一实例合并并发扫描，异步分批读取并及时让出执行权；本次不新增扫描目录/文件数量或存储配额上限。不阻塞主线程、工作流执行或配置写锁；沿用现有请求取消/超时，扫描中断返回部分状态。扫描只读，不占维护排他窗口；恢复/目录切换期间中止或作废当前扫描，避免展示混合实例结果。

#### 刷新与接口

进入页面先展示最近一次结果及其时间，无结果时启动后台扫描；“刷新”主动重新统计，不轮询触发新扫描。同一实例最多一个活动扫描，多次请求复用该扫描。刷新时保留旧值并标记“统计中”，失败时保留旧值并明确已过期，不能伪装为最新。

拟议接口（遵守现有设置访问保护）：

- `GET /api/storage/usage`：最近结果及 `idle/scanning/completed/partial/failed` 状态，未扫描时结果为 null。
- `POST /api/storage/usage/scan`：启动或复用扫描，返回 scanId；不接受根目录或文件路径参数。
- `GET /api/storage/usage/scans/:id`：轮询状态和结果；仅活动扫描期间轮询，离开页面停止轮询但不需要停止共享扫描。

结果包含 `dataDir`、`scanId`、`startedAt/completedAt`、`allocatedBytes/logicalBytes/fileCount`、分类与项目明细、文件系统容量、排除/错误计数及 `partial`。字节数采用十进制字符串避免大整数精度丢失，页面统一格式化为 KiB/MiB/GiB。失败摘要不得暴露敏感文件名或内容。

统计结果只存内存缓存，重启后重新扫描，不新增数据库表或运行历史。文件系统容量单独记录采样时间，扫描完成不代表其中所有文件同时处于该大小。

## 9. 数据、恢复与数据库审核

建议首期项目和 SSH 引用采用本机原子 JSON；运行固定配置、实际 SHA、准备耗时和工具策略版本沿用 node_attempts 的 execution_json。入队快照和 lease 采用受控运行文件，并与现有入队/快照生命周期协调，防止失败入队留下有效任务或悬空资源。

预期无需新增表、索引或迁移，但这仍需实施前验证：

- 现有运行快照能否承载内部项目修订，不混入用户业务输入或不可变发布定义。
- 开始 fetch 前、固定 SHA 后、完成节点事务前重启的恢复顺序；沿用 interrupted 语义，不自动重复分析。
- 项目引用扫描覆盖草稿、发布版本、排队/活动运行，不能只扫描当前发布指针。
- 项目执行必须纳入配置恢复/维护活动门禁，避免目录回收或恢复与运行并发。

若需要新增绑定表或改字段/约束，必须在本 feature 内另写 schema-review，获得用户明确批准后再实施。本文不构成数据库审核通过；本次只新增设计文档。

项目本机配置、SSH 私钥和缓存不自动进入配置 Git 快照。首期不做跨设备自动映射；缺失项目依赖须在恢复预览阶段阻止相关工作流应用，用户先创建匹配项目再重新预览，不可留到运行中才发现。

## 10. 错误与验收标准

错误码建议包括：`PROJECT_NOT_AVAILABLE`、`PROJECT_CAPABILITY_UNSUPPORTED`、`PROJECT_RISK_NOT_ACCEPTED`、`SSH_HOST_UNTRUSTED`、`SSH_AUTH_FAILED`、`PROJECT_BRANCH_NOT_FOUND`、`PROJECT_FETCH_FAILED`。沿用已有超时、取消和输出 Schema 错误，API 不回显底层敏感命令或 stderr。

必须验证：

1. 通过真实 SSH 测试仓库，首次 clone，远端新增提交后再次运行 fetch，结论对应新 SHA；Orchard 管理操作无 push，不把此结果扩展为 Agent 无法 push 的证明。
2. 未知/变更主机密钥、加密密钥未解锁、错误 deploy key、无读取权限、SSH 端口、网络中断与分支删除均安全失败。
3. 同项目并发、不同项目并发、排队后改配置、fetch 时远端变化，均对应固定项目修订与 SHA，互不污染。
4. 实际读取至少两个源码文件，结论包含可核验的文件/行号引用，最终 JSON 成为节点输出且可被后续节点/顶层 result 消费。
5. 无项目节点行为与工具权限不变；不支持的 Provider 发布/运行前明确阻止。
6. 验证启用项目必须确认风险，Orchard 自己不注入或回显凭据。验证项目场景可以使用工具和命令；不要求拒绝越界访问，不声称 Agent 输出或命令副作用可被完全脱敏。测试不得读取真实私钥或对真实远端执行推送。
7. clone/fetch/Agent 各阶段取消、超时、磁盘满、进程崩溃和清理失败不遗留活动锁，不误报成功、不自动离线降级或重新执行。
8. Orchard 准备快照不执行 hooks/filters、不下载 LFS/子模块对象；未展开项明确呈现。异常路径安全失败，大仓库不施加本次新增配额；不承诺约束 Agent 后续自行执行的命令。
9. 项目缺失/禁用、凭据轮换、跨设备恢复依赖、活动维护门禁、敏感输入脱敏均覆盖自动化测试。
10. 类型检查、Pi/Codex 各自的目录/工具调用/结构化输出集成测试、真实 SSH 集成；页面实际检查浅/深/系统主题、长地址、窄屏与键盘操作。记录未完成的验证，不能只以 mock 测试替代端到端验收。
11. 默认及自定义 data-dir 下，clone 缓存、staging、快照和项目 Agent 会话均位于实际根目录内；准备/分析不在系统临时目录创建这些资源。
12. 存储页面覆盖整个数据目录；使用已知大小夹具验证分类互斥、合计与项目下钻一致，覆盖隐藏文件、SQLite WAL/SHM、孤立缓存、稀疏文件、硬链接、符号链接和不支持 allocated 的平台。
13. 扫描大目录不阻塞运行；并发刷新复用扫描；权限不足、并发删除、扫描中断、磁盘容量读取失败、重启与恢复期间正确显示部分/失败/过期状态，不把无法统计的内容显示为零。页面没有删除或清理副作用。
