# 草稿运行测试：待审核的数据库变更

状态：已于 2026-11-04 获得用户批准；本记录保留最终实施口径与约束。

## 行为

草稿编辑页增加“运行测试”。测试前保存修改，使用期望修订号检查并发冲突，通过校验后冻结流程定义、模型配置和编译后的脚本，创建独立运行。测试不发布工作流、不增加发布版本号、不改变当前发布版本。

运行沿用现有执行队列、节点输入输出、日志、取消和重启恢复机制。运行详情标明“草稿测试 · 修订 N”，提供返回原草稿的入口。编辑草稿不影响已经创建的测试运行，重新测试使用草稿的新快照。

测试与正式运行一样实际执行脚本和 Agent 调用。

## 待审核的表结构变更

只调整 `runs` 表：

| 字段 | 调整 | 用途 |
| --- | --- | --- |
| `workflow_version_id` | 允许 NULL，保留版本外键 | 正式运行引用不可变发布版本，草稿测试不创建发布版本 |
| `draft_id` | 新增可空 TEXT，外键指向 `drafts(id)` | 标识测试来源草稿 |
| `draft_revision` | 新增可空 INTEGER | 记录测试使用的草稿修订号 |
| `snapshot_path` | 新增可空 TEXT | 引用现有文件存储中的不可变测试快照，包含冻结后的 workflow.json、layout.json 与编译脚本 |

新增 CHECK 约束：正式运行必须有 `workflow_version_id` 且三个草稿字段为空；草稿测试必须没有 `workflow_version_id`，且三个草稿字段均非空，`draft_revision >= 0`。

数据库 schema 版本从 1 升至 2。迁移时在事务中重建 `runs`，保留全部现有运行及引用它的节点记录、事件和产物，重建 `queued_runs` 索引，校验外键后提交。不修改已有版本、工作流、草稿及节点运行表的字段。

实施时覆盖旧数据库升级、测试后继续编辑、无发布版本的全新草稿测试、并发修订冲突、输入校验、取消与重启恢复。审核通过后才编写和执行结构迁移。

## 已完成且无表结构变更的版本功能

- 编辑同一工作流继续未发布草稿，发布时版本号递增。
- 从选中版本复制为独立的新工作流，分配全新 ID，首次发布为 v1。
- 查看历史版本、版本创建时间及当前发布标记。
- 将历史版本还原为同一工作流的草稿，发布生成新版本，保留完整历史；已有未发布草稿时拒绝覆盖。
